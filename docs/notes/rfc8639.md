# RFC 8639 — Subscription to YANG Notifications

Source: /tmp/claude-0/-home-user-arcana/c5b51962-0391-52a9-87d4-18bb94158d90/scratchpad/rfc/rfc8639.txt (September 2019, Standards Track, 4315 lines, read in full).

## Purpose
Transport-agnostic subscription model for YANG event streams, replacing RFC 5277's
`<create-subscription>`: dynamic subscriptions (RPCs) and configured subscriptions
(datastore entries, optional feature), multiple subscriptions per transport session,
modification in flight, QoS, negotiation hints on failure, subscription state change
notifications, monitoring counters. RFC 8641 (YANG-Push) builds on it for datastore
updates. Transport bindings: NETCONF (RFC 8640), RESTCONF (draft restconf-notif), and —
for cblink — one to be written.

## Terminology (1.2)
event, event record (an instance of a `notification`), event stream (named, chronologically
ordered), event stream filter (boolean test; XPath or subtree), notification message,
publisher, receiver, subscriber (= receiver for dynamic subscriptions), subscription,
dynamic vs configured subscription.

## Event streams (2.1)
Named; the only reserved name is `NETCONF` (all event records except those explicitly
excluded). Event records of a data-node notification include the hierarchy of ancestor
nodes with keys (7950 §7.16.2). Access control may silently exclude records (RFC 8341
§3.4.6); subscription state change notifications are never filtered. If the receiver loses
access to a stream, the subscription MUST be terminated. Records MUST NOT be delivered out
of stream order.

## Filters (2.2) and QoS (2.3)
Filter = boolean over the event record; never strips content. XPath (`yang:xpath1.0`,
feature `xpath`) or subtree (RFC 6241 §6, feature `subtree`). No filter = everything.
QoS: `dscp` (feature dscp; different DSCPs need different TCP sessions, else
`dscp-unavailable`), `weighting` 0..255 (feature qos; proportional bandwidth),
`dependency` on another subscription (feature qos; parent dequeued first; silently dropped
if the referenced id is missing).

## Dynamic subscriptions (2.4)
State machine: establish → active ⇄ suspended (insufficient CPU/bandwidth,
`subscription-suspended` / `subscription-resumed`); modify keeps the previous state on
failure; delete/kill/stop-time → end. Lifetime bound to the transport session.

RPCs (trees verbatim):
```
+---x establish-subscription
   +---w input
   |  +---w (target)
   |  |  +--:(stream)
   |  |     +---w (stream-filter)?
   |  |     |  +--:(by-reference)
   |  |     |  |  +---w stream-filter-name          stream-filter-ref
   |  |     |  +--:(within-subscription)
   |  |     |     +---w (filter-spec)?
   |  |     |        +--:(stream-subtree-filter)
   |  |     |        |  +---w stream-subtree-filter?   <anydata> {subtree}?
   |  |     |        +--:(stream-xpath-filter)
   |  |     |           +---w stream-xpath-filter?     yang:xpath1.0 {xpath}?
   |  |     +---w stream                               stream-ref
   |  |     +---w replay-start-time?                   yang:date-and-time {replay}?
   |  +---w stop-time?                                 yang:date-and-time
   |  +---w dscp?                                      inet:dscp {dscp}?
   |  +---w weighting?                                 uint8 {qos}?
   |  +---w dependency?                                subscription-id {qos}?
   |  +---w encoding?                                  encoding
   +--ro output
      +--ro id                            subscription-id
      +--ro replay-start-time-revision?   yang:date-and-time {replay}?

yang-data establish-subscription-stream-error-info
  +--ro establish-subscription-stream-error-info
     +--ro reason?                   identityref
     +--ro filter-failure-hint?      string

+---x modify-subscription
   +---w input
      +---w id                                          subscription-id
      +---w (target) ... (stream-filter only; stream itself not modifiable)
      +---w stop-time?                                  yang:date-and-time
yang-data modify-subscription-stream-error-info { reason?, filter-failure-hint? }

+---x delete-subscription   +---w input +---w id  subscription-id     (same session only)
+---x kill-subscription     +---w input +---w id  subscription-id     (nacm:default-deny-all; any session)
yang-data delete-subscription-error-info { reason (mandatory) }
```
- Encoding: if absent, the encoding of the RPC itself MUST be used. `encoding` is an
  identityref with base `encoding` (`encode-xml`, `encode-json`); transports may define
  `encode-cbor` derived from `configurable-encoding` (explicitly foreseen in 2.4/4).
- Replay (2.4.2.1): `replay-start-time` MUST be in the past; if earlier than the log,
  `replay-start-time-revision` is returned; `replay-completed` marks the end of history;
  stream entries expose `replay-support`, `replay-log-creation-time`,
  `replay-log-aged-time`.
- Error identities per RPC: establish → dscp-unavailable, encoding-unsupported,
  filter-unsupported, insufficient-resources, replay-unsupported; modify →
  filter-unsupported, insufficient-resources, no-such-subscription; delete/kill →
  no-such-subscription. Errors travel in the transport's RPC error structure plus the
  yang-data hints (MUST be included if the reason is not elsewhere or hints are given).
- Event records matching new terms MUST NOT be sent before the RPC reply.

## Configured subscriptions (2.5, feature `configured`)
Installed via configuration under `/subscriptions`; persist across reboots and transport
loss; multiple receivers; extra parameters `transport` (identityref base `transport`),
`receivers/receiver[name]` with transport-specific augmentation for connection parameters
(MUST be provided by at least one augmenting module, e.g. Appendix A's `foo` with
address/port and a `when derived-from(../../../transport, "fsn:foo")`), egress selection
`source-interface` (feature interface-designation) or `source-vrf` (feature supports-vrf,
leafref to `/ni:network-instances/network-instance/name`) + `source-address`.
State machine: valid / invalid / concluded; per receiver connecting → active → suspended /
disconnected; `reset` action returns a receiver to connecting. State change
notifications: `subscription-started` (configured only; carries all parameters incl. the
resolved filter), `subscription-modified`, `subscription-terminated` (reasons
no-such-subscription, filter-unavailable, stream-unavailable, suspension-timeout),
`subscription-suspended` (insufficient-resources, unsupportable-volume),
`subscription-resumed`, `subscription-completed` (stop-time reached), `replay-completed`.
Configured replay (`configured-replay`, empty): replay from the later of log creation,
aged time and boot time; `replay-previous-event-time` lets the receiver detect gaps.
Call home (RFC 8071) for connectivity.

## Event record delivery (2.6)
Notification message MUST include `eventTime` at the top (RFC 5277 §4):
`<notification><eventTime>…</eventTime><link-failure>…</link-failure></notification>`.
Dynamic subscription messages go on the establishing session; configured on the
configured transport.

## Subscription state change notifications (2.7)
Tagged with the extension `sn:subscription-state-notification`; never in any stream,
never filtered, never replayed, delivered only to affected receivers, inserted into the
receiver's message sequence.

## Monitoring (2.8) and conformance (2.9)
`/subscriptions` in `<operational>` lists dynamic and configured subscriptions with
`configured-subscription-state` (valid|invalid|concluded), per receiver
`sent-event-records`, `excluded-event-records` (filter + access control), `state`.
A publisher MUST advertise `ietf-subscribed-notifications` in its YANG library with the
features it supports: encode-xml, encode-json, configured, supports-vrf, qos, xpath,
subtree, interface-designation, dscp, replay.

## Data trees (section 3) verbatim
```
+--ro streams
   +--ro stream* [name]
      +--ro name                        string
      +--ro description                 string
      +--ro replay-support?             empty {replay}?
      +--ro replay-log-creation-time    yang:date-and-time {replay}?
      +--ro replay-log-aged-time?       yang:date-and-time {replay}?

+--rw filters
   +--rw stream-filter* [name]
      +--rw name                           string
      +--rw (filter-spec)?
         +--:(stream-subtree-filter)
         |  +--rw stream-subtree-filter?   <anydata> {subtree}?
         +--:(stream-xpath-filter)
            +--rw stream-xpath-filter?     yang:xpath1.0 {xpath}?

+--rw subscriptions
   +--rw subscription* [id]
      +--rw id                                           subscription-id
      +--rw (target)
      |  +--:(stream)
      |     +--rw (stream-filter)? ... (as above)
      |     +--rw stream                                 stream-ref
      |     +--ro replay-start-time?                     yang:date-and-time {replay}?
      |     +--rw configured-replay?                     empty {configured,replay}?
      +--rw stop-time?                                   yang:date-and-time
      +--rw dscp?                                        inet:dscp {dscp}?
      +--rw weighting?                                   uint8 {qos}?
      +--rw dependency?                                  subscription-id {qos}?
      +--rw transport?                                   transport {configured}?
      +--rw encoding?                                    encoding
      +--rw purpose?                                     string {configured}?
      +--rw (notification-message-origin)? {configured}?
      |  +--:(interface-originated)
      |  |  +--rw source-interface?    if:interface-ref {interface-designation}?
      |  +--:(address-originated)
      |     +--rw source-vrf?          -> /ni:network-instances/network-instance/name {supports-vrf}?
      |     +--rw source-address?      inet:ip-address-no-zone
      +--ro configured-subscription-state?               enumeration {configured}?
      +--rw receivers
         +--rw receiver* [name]            (min-elements 1)
            +--rw name                      string
            +--ro sent-event-records?       yang:zero-based-counter64
            +--ro excluded-event-records?   yang:zero-based-counter64
            +--ro state                     enumeration  active|suspended|connecting|disconnected
            +---x reset {configured}?
               +--ro output +--ro time    yang:date-and-time
```
Module `ietf-subscribed-notifications@2019-09-09` (prefix sn) imports inet, if, nacm, ni,
rc, yang. Typedefs: `encoding` (identityref), `stream-filter-ref`, `stream-ref`
(leafrefs), `subscription-id` (uint32), `transport` (identityref). The `stream` leaf in the
RPC input uses `stream-ref { require-instance false; }`. ID space recommendation: lower
half for configured, upper half for dynamic.

## Transport requirements (section 7)
Multiple establish-subscription per session; mutual authentication; event records and
state change notifications on the same session as each other (ordered); the transport
spec MUST list supported encodings and the default.

## Mapping to cblink
1. A cblink **push stream** is the natural transport binding for a dynamic subscription:
   `establish-subscription` is an rpc (POST-like `do`) whose success reply carries `id`;
   the event records then flow either as cblink `NOTIFY` frames (multicast group ≈ stream)
   or, better, on a cblink stream opened by the establish request (the stream id is the
   transport handle; flow control gives the "suspended on insufficient bandwidth"
   semantics for free: when credit runs out the publisher can emit
   `subscription-suspended { unsupportable-volume }` instead of dropping, exactly what
   cblink today signals with CODE=ENOBUFS on the next notification).
   `modify/delete/kill-subscription` are plain rpcs. Closing the stream = deleting the
   subscription (dynamic subscription lifetime bound to the session).
2. Encoding identity for the binding: define `cblink:encode-cbor-sid` with base
   `sn:configurable-encoding`... strictly `encoding` base `sn:encoding` and
   `transport` identity `cblink:cblink` with base `sn:transport`, plus the receiver
   augmentation (`address`, `port`, TLS parameters) if configured subscriptions are
   wanted (the console as a configured receiver of every agent is the natural fit: it
   survives console restarts and uses call-home-like reconnects — cblink already has
   `arcana-enrol`-style reconnection).
3. cblink multicast groups map to event streams: `streams/stream[name]` lists them; the
   control family's `subscribe {family-id, group-id}` becomes `establish-subscription
   {stream}`; the group's `auth` flag becomes a NACM notification rule.
4. Filters: `stream-xpath-filter` needs the XPath evaluator over the notification instance;
   `stream-subtree-filter` (RFC 6241 §6 subtree filtering) is a simple structural match —
   support subtree first, declare only feature `subtree` if XPath is not ready.
5. `eventTime` must be carried: in YANG-CBOR there is no `<notification>` envelope defined;
   CORECONF sends bare `{notification-SID: content}`. cblink should define a structure
   `cblink:notification { eventTime; <anydata notification> }` or put eventTime in a
   framework attribute (see design doc).
