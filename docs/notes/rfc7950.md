# RFC 7950 — The YANG 1.1 Data Modeling Language

Source: /tmp/claude-0/-home-user-arcana/c5b51962-0391-52a9-87d4-18bb94158d90/scratchpad/rfc/rfc7950.txt (August 2016, Standards Track, 12155 lines, read in full including the ABNF in section 14).

## Purpose

YANG models configuration data, state data, RPCs/actions and notifications. A module is a
tree of schema nodes with types and constraints; the XML encoding and NETCONF mapping are
defined here, other encodings (JSON 7951, CBOR 9254) and protocols (RESTCONF, CORECONF)
elsewhere. Version 1.1 is a maintenance release of RFC 6020 with a few incompatible changes
(escapes in double-quoted strings, no quotes in unquoted strings, `when`/`if-feature` illegal
on list keys, legal character set, noncharacters illegal in strings) and many additions
(action, anydata, notifications tied to data nodes, if-feature expressions, `modifier
invert-match`, `must` in input/output/notification, require-instance on leafref, multiple
revisions imported, conditionally-mandatory augments, new XPath functions, identities with
multiple bases, enum/bits subtyping, leaf-list defaults, non-unique state leaf-lists,
empty/leafref in unions, empty keys).

## Terminology (section 3) — the vocabulary the generator must model
- **data node**: container, leaf, leaf-list, list, anydata, anyxml (instantiable).
- **schema node**: data nodes + action, choice, case, rpc, input, output, notification.
- **data definition statement**: container, leaf, leaf-list, list, choice, case, augment,
  uses, anydata, anyxml.
- **mandatory node**: leaf/choice/anydata/anyxml with `mandatory true`; list/leaf-list with
  `min-elements > 0`; a non-presence container with at least one mandatory child.
- **top-level data node**: directly under module/submodule.
- presence vs non-presence container; interior node; value space; conformance; deviation.

## Language concepts (section 5)
- Module = single data model; submodules contribute to it (no SIDs, no namespace of their
  own). Module names MUST be unique on a server. `include` lists submodules; `import` makes
  external definitions available via a prefix. No circular imports. A 1.1 submodule sees all
  definitions of its module and sibling submodules without include.
- Import by revision (`revision-date`): typedef/grouping/extension/feature/identity are
  taken from that revision; without it, "undefined which revision". Multiple revisions of a
  module may be imported with different prefixes.
- Multiple top-level data nodes per module = multiple hierarchies.
- File layout: `name[@revision].yang` / `.yin`.
- Namespaces: each module has an XML namespace URI (IANA for RFC modules).
- Name resolution for grouping/type/identity: static scoping — resolved where *defined*,
  not where used. Nested typedef/grouping are lexically scoped; MUST NOT shadow outer ones.
- Conformance: features (`feature`/`if-feature`), deviations (`deviation`), basic behavior.
  A server MUST NOT implement more than one revision of a module. Servers announce modules
  through ietf-yang-library (RFC 7895 → now 8525) with `conformance-type` implement|import.
  If A uses B's nodes in augment/path, server MUST implement a revision of B with them.
- Datastore modification by the server itself (system-generated values) is allowed.

## Syntax (section 6)
- UTF-8; legal chars = `yang-char` (tab, CR, LF, and Unicode minus C0 controls, surrogates,
  noncharacters). Lines end LF or CRLF.
- Comments `//` and `/* */` (never inside quoted strings).
- Tokens: keyword, string (quoted or unquoted), `;`, `{`, `}`. Keyword = YANG keyword or
  `prefix:extension-keyword`. Case-sensitive.
- Unquoted string: no whitespace, no quotes, no `;{}`, no comment sequences; backslash not
  special. Any keyword may appear as an unquoted string.
- Double-quoted: leading whitespace on continuation lines stripped up to the column of the
  opening quote (tab = 8 spaces), trailing whitespace before line breaks stripped; escapes
  `\n \t \" \\` ONLY (any other backslash sequence is an error in 1.1). Single-quoted:
  verbatim, cannot contain `'`. `+` concatenates quoted strings (whitespace/comments allowed
  around `+`). Order: trim, then escapes, then concatenation.
- Identifiers: `(ALPHA / "_") *(ALPHA / DIGIT / "_" / "-" / ".")`; MUST support 64 chars;
  case-sensitive; may be quoted.
- Identifier namespaces (6.2.1): modules+submodules global; extensions, features, identities
  per module (incl. submodules); typedefs and groupings scoped to the parent node and its
  descendants (no redefinition below); data/choice/rpc/action/notification/anydata/anyxml
  names share one namespace scoped to the parent node, except that under a case node the
  scope is the closest non-case/non-choice ancestor; cases share a namespace per choice.
  Forward references allowed.
- Statement = `keyword [argument] (";" | "{" *statement "}")`. Extensions (`prefix:kw`) may
  appear as substatements anywhere; unsupported extensions MAY be ignored entirely.
- XPath (6.4): YANG uses XPath 1.0 as *notation*; an implementation "is not required to
  implement an XPath interpreter but MUST ensure that the requirements encoded in the data
  model are enforced". Expressions MUST be syntactically correct and all prefixes resolvable.
  Data model = XPath 1.0 with XSLT root-children extension; no document order (expressions
  SHOULD NOT rely on it); numbers are IEEE doubles (64-bit ints/decimal64 lose precision).
- XPath context (6.4.1): namespace decls = imports' prefixes + the module's own prefix;
  unprefixed names = namespace of the current node (inside groupings/typedefs: where used);
  function library = XPath core + section 10; no variables. Accessible tree: config node →
  the datastore; state node → all state + running config; notification → the notification
  instance + state + running (top-level notification is a child of root); rpc/action
  input/output → the operation instance + state + running (rpc node is a child of root; action
  is in place in the data tree). Defaults in use and non-presence containers exist in the
  accessible tree.
- Schema node identifier (6.5): absolute `/a/b` or descendant `a/b`; prefixes required for
  foreign nodes; case names MUST appear explicitly.

## Statements (section 7) — complete list with semantics a validator must enforce

### Module-level
| Statement | Semantics |
|---|---|
| module | name (identifier); substatements: yang-version(1), namespace(1), prefix(1), import*, include*, organization?, contact?, description?, reference?, revision*, body (extension, feature, identity, typedef, grouping, data-def, augment, rpc, notification, deviation). |
| submodule | belongs-to(1) with prefix; no namespace/prefix of its own. |
| yang-version | MUST be "1.1" for this spec; absent or "1" = RFC 6020. |
| namespace | URI. |
| prefix | identifier; unique within module incl. imports. |
| import | prefix(1), revision-date?, description?, reference?. |
| include | revision-date?; only submodules of this module; one revision per submodule. |
| organization / contact / description / reference | text. |
| revision | `YYYY-MM-DD`; reverse chronological; description/reference. |
| belongs-to | module name + prefix. |

### Types
| Statement | Semantics |
|---|---|
| typedef | name MUST NOT be a built-in type; type(1), units?, default?, status?, description?, reference?. Base type's default is inherited unless overridden; a default MUST be valid under the new restrictions. |
| type | built-in or derived name; substatements (by base): base* (identityref), bit* (bits), enum* (enumeration), fraction-digits? (decimal64, MUST be present), length? (string, binary), path? (leafref, MUST), pattern* (string), range? (numeric, decimal64), require-instance? (leafref, instance-identifier), type* (union, ≥1). |
| units | text. |
| default | string valid per type; MUST NOT be present with `mandatory true`; MUST NOT depend on an if-feature'd enum/bit/identity. |

### Data definition
| Statement | Semantics |
|---|---|
| container | presence? (presence container has meaning by itself; non-presence container with no children ≡ absent, may be omitted/auto-deleted); must*, when?, if-feature*, config?, status?, typedef*, grouping*, data-def*, action*, notification*. |
| leaf | type(1), units?, must*, default?, config?, mandatory?, when?, if-feature*, status?. Exists 0..1 times. Value conceptually in canonical form. |
| leaf-list | type(1), default* (1.1), must*, config?, min-elements?, max-elements?, ordered-by?, when?, if-feature*. **In config data, values MUST be unique**; state leaf-lists may repeat. `default` MUST NOT be present if min-elements ≥ 1. |
| list | key? (MUST for config lists), unique*, must*, config?, min-elements?, max-elements?, ordered-by?, when?, if-feature*, typedef*, grouping*, data-def+ (≥1), action*, notification*. |
| key | space-separated child leaf identifiers (may come from groupings); no duplicates; all keys MUST be given when an entry is created; defaults and `mandatory` on key leaves are ignored; key leaves MUST have the same `config` as the list; any type incl. `empty` (1.1); key leaves MUST NOT have `when` or `if-feature`. |
| unique | space-separated descendant schema node ids, each a leaf; all config or all state; the tuple (including defaults) MUST be unique among entries **in which all referenced leafs exist or have defaults** (entries missing any referenced leaf are ignored). |
| choice / case | choice is a schema node, not a data node; at most one case present at a time; creating a node of one case implicitly deletes the other cases' nodes; shorthand case (single data-def directly under choice, case name = node name); child names unique across all cases; `default <case>` (MUST NOT with mandatory true; no mandatory nodes directly under the default case; defaults under a case apply only if that case is present or default); `mandatory true` → at least one node of exactly one case MUST exist. |
| anydata | unknown set of YANG-modeled nodes; opaque for editing (whole value only); cannot be augmented; 0..1 instance; SHOULD NOT be config; mandatory?, must*, when?, if-feature*, config?. |
| anyxml | unknown chunk of XML (any CBOR item in 9254); same substatements; prefer anydata. |
| grouping | not a data definition; copied by `uses`; MUST NOT be recursive; identifiers resolved where defined; may contain actions/notifications (then not usable everywhere). |
| uses | copies the grouping's nodes into the current schema tree, then applies refine* and augment* (descendant form); nodes bound to the *using* module's namespace; when?, if-feature*, status?. |
| refine | descendant target; may set/override: default (leaf, choice, leaf-list set), description, reference, config, mandatory (leaf/anydata/anyxml/choice), presence (container), must (add), min/max-elements, if-feature (add), extension properties. |
| augment | target = container, list, choice, case, input, output or notification (absolute form at top level; descendant form under uses); adds container/leaf/list/leaf-list/uses/choice (+ action/notification for container/list targets; case for choice targets); MUST NOT add duplicate names from the same module; nodes are in the augmenting module's namespace; **mandatory config nodes added to another module's target MUST be conditional with `when`**. |
| when | XPath → boolean; node valid only when true; MUST NOT be on key leaves (or on `uses` of a grouping providing key leaves). Context node: for augment → the target node (or closest data-node ancestor, or root); for uses/choice/case → closest data-node ancestor (or root); otherwise a dummy node replacing the node itself. The accessible tree is tentatively altered (augment/uses/choice/case nodes removed; or the node replaced by a dummy). Referenced nodes' own `when`s are evaluated first; no circular `when`s. |
| must | XPath → boolean, evaluated once per node in the accessible tree; context node = the node (notification/input/output: the notification/operation node); error-message?, error-app-tag?. All MUST be true in a valid tree. Comparisons use canonical values. "Conceptually evaluated" — hand-written code allowed. |
| config | true/false; default inherited from parent (case → choice's parent); top-level default true; nothing under config false may be config true. Ignored in rpc/action input/output and notifications. |
| status | current (default) / deprecated / obsolete (SHOULD NOT be implemented); current MUST NOT reference deprecated/obsolete in the same module; deprecated MUST NOT reference obsolete. |
| min-elements | non-negative int, default 0; enforced depending on the closest non-non-presence-container ancestor (none → always; case → if any other node of the case exists; else if the ancestor exists). |
| max-elements | positive int or `unbounded` (default). |
| ordered-by | system (default; deterministic order SHOULD be used) / user (order carried by the client; NETCONF `insert`/`key`/`value` attributes: first, last, before, after). Ignored for state data, rpc output, notifications. |
| mandatory (leaf/anydata/anyxml) | true → the node MUST exist (in the same ancestor-dependent sense as min-elements). |

### Operations and notifications
| Statement | Semantics |
|---|---|
| rpc | top-level; defines an rpc node plus `input` and `output` schema nodes (in the module's namespace); if-feature*, status?, typedef*, grouping*, input?, output?. |
| action | tied to a container or list (1.1); MUST NOT be under rpc/action/notification; MUST NOT be under a keyless list; not at top level or in a case; invocation names the data node instance (all ancestors + keys) plus the action and its input. Only one action per `<rpc>`. |
| input / output | data-def+ (≥1), must* (1.1), typedef*, grouping*. mandatory leaves MUST be present; defaults in use as for leaves (server for input, client for output); `config` ignored; nodes whose `when` is false MUST NOT be present. Augmentable. |
| notification | top-level or tied to a container/list (1.1); not under rpc/action/notification; not under a keyless list; not in a case; data-def*, must*, typedef*, grouping*, if-feature*, status?. Instance of a data-node notification carries the ancestor path with keys. Mandatory leaves MUST be present; defaults apply client-side; config ignored. |

### Identities, extensions, conformance
| Statement | Semantics |
|---|---|
| identity | globally unique abstract untyped name; base* (0..n in 1.1: derived from all of them); if-feature*; derivation is irreflexive and transitive; no cycles. |
| extension | argument? (with yin-element? true/false); defines a new `prefix:keyword` statement usable anywhere; substatements of an extension instance MUST be YANG statements. |
| feature | name; if-feature* (a feature may depend on others; server supporting it MUST support them); status?. No cycles. |
| if-feature | boolean expression: `not`, `and`, `or`, parentheses; precedence () > not > and > or; prefixed feature names resolve via imports. Allowed on data-def statements, enum, bit, identity, refine, uses, augment, rpc, action, notification, feature, case, choice, list, leaf-list, container, leaf, anydata, anyxml. NOT on key leaves. If false, the node is ignored by the server (absent from the schema). |
| deviation | absolute target; deviate `not-supported` (node not implemented) | `add` (add properties that don't exist: config, default*, mandatory, max/min-elements, must*, unique*, units) | `replace` (type, units, default, config, mandatory, min/max-elements) | `delete` (units, must*, unique*, default* — argument string MUST match). MUST never be in a published standard; resulting model after all deviations MUST be valid. |

## Constraint enforcement model (section 8) — what a validator must check

Always true in any data tree (checked at **payload parse** time):
1. every leaf value matches its type including `range`, `length`, `pattern` → `invalid-value`
   (+ error-app-tag/error-message from the constraint);
2. all key leaves present for every list entry → `missing-element`;
3. nodes from at most one case per choice → `bad-element`;
4. no node present whose `if-feature` is false → `unknown-element`;
5. no node present whose `when` is false → `unknown-element`;
6. (NETCONF) `insert` before/after values valid for the key type → `bad-attribute`;
   `before`/`after` only on ordered-by user lists → `unknown-attribute`.

True in a **valid** data tree (checked at **validation** time, after edit-config on running/
startup, or at commit/validate for candidate):
7. all `must` true → `operation-failed` / `must-violation` (or the must's own app-tag);
8. referential integrity of `path` (leafref with require-instance true) and
   instance-identifier with require-instance true → `data-missing` / `instance-required`;
9. all `unique` → `operation-failed` / `data-not-unique` (+ `<non-unique>` instance ids);
10. `mandatory` for leafs and choices (unless an ancestor's when/if-feature is false) →
    `missing-element` / (mandatory choice: `data-missing` / `missing-choice`);
11. `min-elements`/`max-elements` (same proviso) → `operation-failed` /
    `too-few-elements` / `too-many-elements` (reported once per list node).
The running datastore MUST always be valid.

Edit-config processing (8.3.2) MUST detect: delete of non-existent data, create of existing
data (`data-exists`), insert before/after non-existent entries (`bad-attribute` /
`missing-instance`), modification of a node whose `when` is false (`unknown-element`).

Server-side side effects (8.2): creating nodes of one case deletes the other cases; a
modification that makes some node's `when` false deletes that node.

Per-node edit semantics for NETCONF operations merge/replace/create/delete (7.5.8, 7.6.7,
7.7.9, 7.8.6, 7.10.3, 7.11.3): merge/replace create if absent (and set value); create errors
with `data-exists` if present; delete errors with `data-missing` if absent (NETCONF `remove`
is the silent variant). Leaf-list entries can be created/deleted, not modified. anydata/anyxml
are replaced whole. For ordered-by user lists, merge/replace with insert+key moves an existing
entry; a replace covering the whole list takes the request order.

## Built-in types (section 9)
| Type | Value space / restrictions | Lexical / canonical |
|---|---|---|
| int8/16/32/64, uint8/16/32/64 | `range` (`a..b \| c \| min..max`, disjoint, ascending, each restriction at least as limiting as the base) | decimal with optional sign; in YANG module defaults also `0x` hex and leading-0 octal; canonical: no `+`, no leading zeros |
| decimal64 | `fraction-digits` 1..18 (MUST be present); value = i × 10^−n with i int64; `range` with decimal bounds | optional sign, digits, optional `.digits`; canonical requires the decimal point, no leading/trailing zeros, zero = `0.0` |
| string | `length` (Unicode *characters*, not bytes; `min`/`max`, ranges), `pattern`* (XSD regex, implicitly anchored, ANDed; `modifier invert-match`); characters per `yang-string` (no C0 controls except tab/CR/LF, no surrogates, no noncharacters) | identity; no Unicode normalisation |
| boolean | — | `true`/`false` lowercase |
| enumeration | `enum` name (non-empty, no leading/trailing whitespace, unique) with `value` (int32, unique; auto-assigned: first = 0, else highest+1; MUST be explicit after 2147483647); if-feature on enum does not affect numbering; restriction: subset of names, values unchanged | name string |
| bits | `bit` name (identifier syntax) with `position` (0..4294967295, unique, auto-assigned like enum values); restriction: subset, positions unchanged | space-separated names; canonical: single spaces, ordered by position; empty string = no bits |
| binary | `length` in octets | base64 (RFC 4648 §4) |
| leafref | `path` (MUST; XPath subset: absolute `/a/b[k=current()/../x]` or relative `../a/b`; predicates only key equality tests against `current()`-relative paths), `require-instance` (default true: target node with same value MUST exist in the data tree, defaults in use count; config leafref with require-instance true MUST target config); no circular leafrefs; a leafref to an if-feature'd leaf MUST itself be conditional on at least the same features | same as the target leaf |
| identityref | `base`+ (≥1; valid values = identities derived from ALL bases, restricted to implemented modules); cannot be restricted | XML qualified name (prefix per instance encoding; default namespace if unprefixed); string value in XPath = `prefix:name` with the *import* prefix; no canonical form |
| empty | presence only; no default; cannot be restricted | `<leaf/>` |
| union | `type`+ member types (any type incl. empty and leafref in 1.1); value validated against members in order, first match wins; member defaults/units not inherited; a leafref member with require-instance true forces revalidation when the target disappears | per member |
| instance-identifier | `require-instance` (default true; config → target must be config) | XPath subset: `/p:a/p:b[p:key='v'][p:k2='w']`, leaf-list `[.='v']`, keyless list `[3]`; every key MUST have a predicate; empty key = `''`; all names prefixed; no canonical form |

Canonical representation (9.1): values are conceptually stored canonically; XPath compares
canonical forms; implementations MUST accept all lexical forms.

## XPath functions added by YANG (section 10)
- `node-set current()` — the initial context node.
- `boolean re-match(string, pattern)` — XSD regex, anchored.
- `node-set deref(node-set)` — follow a leafref/instance-identifier (first node in document
  order); empty set otherwise.
- `boolean derived-from(node-set, "prefix:identity")`, `derived-from-or-self(...)`.
- `number enum-value(node-set)` — the enum's integer value, NaN otherwise.
- `boolean bit-is-set(node-set, "bit-name")`.
Plus the whole XPath 1.0 core library (string(), concat(), substring(), contains(),
starts-with(), string-length(), normalize-space(), translate(), number(), sum(), floor(),
ceiling(), round(), boolean(), not(), true(), false(), lang(), count(), id(), local-name(),
namespace-uri(), name(), position(), last()) and all 13 axes in principle — though YANG
modules in practice use child, parent (`..`), self (`.`), descendant-or-self (`//`), and
rarely `ancestor::`.

## Updating a module (section 11) — the compatibility rules (relevant to SIDs/versioning)
- New `revision` MUST be added; module name and namespace MUST NOT change; obsolete
  definitions MUST NOT be removed.
- Allowed: new enums/bits (values/positions unchanged — beware auto-numbering), widened
  range/length/pattern, add default (to a leaf with none), add units, add/update reference,
  relax or remove must/when, mandatory true→false, min-elements lower, max-elements higher,
  description edits, add base to identity, remove base from identityref (≥1 left), new
  typedefs/groupings/rpcs/notifications/extensions/features/identities, new data nodes that
  are not mandatory (or are if-feature'd on a new feature), new case, state→config if not
  mandatory, remove if-feature if not mandatory, status current→deprecated→obsolete,
  type replaced by a syntactically/semantically equivalent type, nodes replaced by
  equivalent nodes (e.g. leaves → uses grouping), split into submodules, change prefix.
- Any other semantic change requires a new definition with a new identifier.
- Data definition substatements MUST NOT be reordered (new ones may be inserted anywhere).

## Coexistence with YANG 1 (12), YIN (13)
1.1 modules MUST NOT include 1.0 submodules and vice versa; 1.0 MUST NOT import 1.1 by
revision. YIN = XML form, one element per keyword, argument as attribute or child element
per Table 1 (description/contact/organization/reference/error-message arguments are
elements; others attributes); extensions choose with `yin-element`.

## ABNF (section 14) — size of the grammar a C parser must cover
- ~70 keywords, 1 generic statement shape; the whole grammar is ~1200 lines of ABNF but
  almost all of it is "which substatements may appear under which statement, with which
  cardinality" — a table-driven check. Unordered substatements everywhere except: typedef/
  grouping before data-def; data-def before action/notification (recommended, not required;
  "almost all statements are unordered" and the ABNF gives the canonical order).
- Argument sub-grammars that need their own small parsers: `range-arg`, `length-arg`,
  `key-arg`, `unique-arg`, `schema-nodeid`, `instance-identifier` (for values),
  `path-arg` (leafref), `if-feature-expr`, `date-arg`, `identifier-ref`, and XPath 1.0 for
  `must`/`when`.
- `unknown-statement` = `prefix:identifier [string] (";" | "{" ... "}")` — extensions
  nest arbitrary statements.

## Security (17)
YANG parsers MUST be robust against malformed modules — a module from an untrusted source is
an attack surface on the generator (cblink-gen already runs under capsicum for this reason).

## What this means for a C implementation (feeds cblink-yang-design.md)

**Static (compile-time, policy-table) checks**: type kind, integer ranges (incl. decimal64
scaled int64 ranges), string length in *characters* (needs UTF-8 code-point counting, not
byte length — cblink's `min-len`/`max-len` are bytes), string `pattern` (XSD regex → needs a
regex engine at validation time; can be compiled to a DFA/NFA table at generation time or
checked with a runtime XSD-regex matcher; POSIX regex(3) in libc is *not* XSD regex:
`\d`, `\p{N}`, `\w`, `\i`, `\c` classes and anchoring differ — translation is possible for
most IETF patterns, with a residue), enum membership, bits membership, identityref
membership (set of derived identities, computed at generation time — bases closed over
implemented modules), binary length, empty, union (ordered member try), presence of keys,
single case per choice, mandatory (with the ancestor rule — which is static given the tree
shape), min/max-elements, config-false nodes rejected in edits, if-feature (static once the
server's feature set is fixed at generation time), unique across entries of one message
(partial: full `unique` needs the whole list, i.e. the datastore).

**Runtime (needs an evaluator over the data tree / datastore)**: `when` (accessible tree
= datastore + the edit), `must`, leafref `require-instance`, instance-identifier
`require-instance`, `unique` across existing entries, `min-elements` across the datastore
after merge, mandatory after merge (a merge that adds a container without its mandatory
child is only invalid if the datastore does not already hold the child), ordered-by user
insert positions, choice case deletion side effects, `when`-false deletion side effects.

**XPath subset actually needed** by the IETF modules in scope (interfaces, ip, routing,
network-instance, lne, nacm, yang-library, subscribed-notifications, yang-push): location
paths with child/parent/self/descendant-or-self axes and name tests, predicates with `=`,
`!=`, `and`, `or`, `not()`, `current()`, `derived-from()`, `derived-from-or-self()`,
`deref()`, `count()`, `boolean()`, string/number literals, comparisons `< <= > >=`,
`contains()`, `starts-with()`, `string-length()`, `re-match()`, `bit-is-set()`,
`enum-value()`, union `|`, `../`. That is roughly 60% of XPath 1.0 grammar but with a tiny
function library; a recursive-descent XPath 1.0 parser + evaluator over an in-memory data
tree with node-set/string/number/boolean types is ~3–4k lines of C (libyang's xpath.c is
~9k lines with full coverage and optimisations).
