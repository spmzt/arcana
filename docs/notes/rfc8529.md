# RFC 8529 — YANG Data Model for Network Instances (ietf-network-instance)

Source: /tmp/claude-0/-home-user-arcana/c5b51962-0391-52a9-87d4-18bb94158d90/scratchpad/rfc/rfc8529.txt (March 2019; 2048 compact lines, read in full).

## Purpose
Models VRFs / VSIs ("network instances", NIs): multiple control-plane and forwarding
instances managed through one device. Each NI is a list entry with a **schema mount point**
(RFC 8528) under which routing/bridging modules are mounted (`shared-schema` MUST be used);
interfaces are assigned to an NI by augmenting `ietf-interfaces`/`ietf-ip` with
`bind-ni-name`. Companion of RFC 8530 (LNEs): an LNE is an independently managed virtual
device; an NI is a VRF inside a device (or inside an LNE). To put an interface in both,
assign it to the LNE first, then within the LNE's interface list to the NI.

## Module ietf-network-instance@2019-01-21 (prefix ni)
Imports if, ip, yangmnt. `name` string mandatory true (key); `enabled` boolean default
true; `description`; `choice ni-type` (empty anchor; type modules add cases with config +
state containers); `choice root-type` **mandatory**: containers `vrf-root`, `vsi-root`,
`vv-root`, each carrying `yangmnt:mount-point "<same-name>"` ("will typically not be an
inline-type mount point"). Augments: `bind-ni-name` leafref on interface, ipv4, ipv6;
assignment failure → error-tag `operation-failed`, error-app-tag `ni-assignment-failed`,
error-info with reason; asynchronous failure → `bind-ni-name-failed` notification (name
mandatory; at least one of the three containers present).

## Rules (3.1–3.4)
- Well-known mount points: `vrf-root` (L3VPN), `vsi-root` (L2VPN), `vv-root` (both);
  new NI types SHOULD reuse them rather than define new mount points.
- **`shared-schema` MUST be used** for NI mount points; mounted modules SHOULD get access to
  device resources via `parent-reference`; an implementation MAY restrict the
  parent-reference to the instance's own interfaces, expressed as:
  ```
  "parent-reference": [
    "/if:interfaces/if:interface[ni:bind-network-instance-name = current()/../ni:name]",
    "/if:interfaces/if:interface/ip:ipv4[ni:bind-network-instance-name = current()/../ni:name]",
    "/if:interfaces/if:interface/ip:ipv6[ni:bind-network-instance-name = current()/../ni:name]"
  ]
  ```
  with `namespace` entries for prefixes `if` and `ni` (plus the longer non-NMDA variant
  referencing `/if:interfaces-state`).
- Instantiation = creating the list entry (RFC 7950 §7.8.6); deletion destroys the NI.
  Setting `bind-ni-name` MUST assign the interface or fail.
- Appendix A: config with two NIs `vrf-red`/`vrf-blue`, each `vrf-root` holding
  `ietf-routing:routing` with an `ietf-ospf` instance; interfaces `eth1`/`eth2` with
  `bind-network-instance-name`; state (NMDA version) shows each `vrf-root` carrying its own
  `ietf-yang-library:yang-library` (module-set `ni-modules`: yang-library, ospf, routing;
  import-only inet/yang/datastores; schema `ni-schema`; datastores running+operational), the
  host `yang-library` (module-set `host-modules` incl. interfaces with features
  arbitrary-names/pre-provisioning, ip, network-instance with feature
  `bind-network-instance-name`, ospf, routing, system, yang-library, schema-mount) and
  `schema-mounts` with the `vrf-root` mount point `shared-schema` + parent-reference
  `/*[namespace-uri() = 'urn:ietf:...:ietf-interfaces']`.

## FreeBSD mapping: FIBs as network instances
FreeBSD's "VRF-lite" is the multi-FIB facility: `net.fibs` (loader tunable, default 1)
creates N independent forwarding tables; processes pick one with `setfib(1)` /
`setfib(2)` / `SO_SETFIB`; interfaces get a default FIB with `ifconfig <if> fib N`
(`SIOCSIFFIB`/`SIOCGIFFIB`, `ifr_fib`), and `ifconfig <if> tunnelfib N` for tunnel
interfaces; `net.add_addr_allfibs` controls whether connected routes are added to every
FIB. There is no FIB name, only a number; FIBs cannot be created at runtime (reboot with
`net.fibs=N` in loader.conf). pf can set FIB per rule (`rtable`). ipfw `setfib`.

| Node | Operational source | Config sink |
|---|---|---|
| `network-instance[name]` | one entry per FIB 1..`net.fibs`−1 (FIB 0 is the host's own default and stays at the top-level `ietf-routing`), name `fib1`.. or user-given names persisted by the agent (`/usr/local/etc/arcana/fibs.conf` mapping name→number); `sysctl net.fibs` | creation is not possible at runtime → `operation-failed`/`ni-assignment-failed` unless the name maps to an existing unused FIB; `loader.conf net.fibs=` write + "reboot required" flag (Arcana already has a pkg-upgrade/reboot notion) |
| `enabled` | always true (FIBs cannot be disabled) | accept true only |
| `description` | agent store | agent store |
| `(ni-type)` | an Arcana case `arcana-ni:fib { fib-number uint16 ro }` (the number is the system identity) | — |
| `(root-type)/vrf-root` mount | `shared-schema`; mounted modules: `ietf-routing` + v4ur/v6ur, `ietf-yang-library`. Mounted `routing/ribs/rib[ipv4-master]/routes` = `sysctl NET_RT_DUMP` with fibnum, `netstat -rn -F N`, netlink `RTA_TABLE=N`; `control-plane-protocol[static]/static-routes` = rc.conf `route_x="-net P gw -fib N"` (route(8) `-fib`) and `setfib N route add` | `route add ... -fib N` / netlink with `RTA_TABLE`; rc.conf `static_routes` entries carrying `-fib N` |
| `if:bind-ni-name` | `SIOCGIFFIB` → `ifr_fib` → name | `SIOCSIFFIB`; rc.conf `ifconfig_<if>="... fib N"`; failure (e.g. loopback) → `ni-assignment-failed` |
| `ip:ipv4/bind-ni-name`, `ip:ipv6/bind-ni-name` | FreeBSD has one FIB per interface, not per AF → report the same value as the interface, origin `system`; or deviate `not-supported` | reject if different from interface binding |
| `bind-ni-name-failed` | `SIOCSIFFIB` returns EINVAL for fib ≥ net.fibs | — |
| `parent-reference` | `/if:interfaces/if:interface[ni:bind-ni-name = current()/../ni:name]` + ipv4/ipv6 variants, exactly the RFC text — so a mounted static route's `outgoing-interface` leafref resolves only to interfaces in that FIB | — |

Processes and jails: `setfib N jexec ...` or jail `fib` parameter? (jail(8) has no fib
parameter; use `setfib` in `exec.start`) — non-VNET jails bound to a FIB are a jail
attribute (`arcana-jails:fib`), not an NI binding. The console shows NIs as "routing
domains".

VSI (`vsi-root`): FreeBSD `if_bridge` is an interface, not an instance → no VSI; do not
mount `vsi-root`. Alternatively vxlan+bridge sets could be modelled later.

## Relevance to the cblink/YANG design
- Needs schema mount support in both generator (mount point = foreign-rooted subtree with
  its own YANG library and SID file set) and runtime (parent-reference node-set injection
  for leafref/XPath). `shared-schema` means one compiled schema for all FIBs — cheap.
- NI root-type choice is mandatory, `vrf-root` container present ⇒ encoded in CBOR as
  `{SID(vrf-root): {SID(rt:routing) − SID(vrf-root): {...}}}` (cross-module delta; or tag
  47 absolute SID at the mount root).
- The `ni-type` choice with no cases is legal YANG (choice may be augmented later); parser
  must accept an empty choice.
