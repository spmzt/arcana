# RFC 8349 — A YANG Data Model for Routing Management (NMDA Version)

Source: /tmp/claude-0/-home-user-arcana/c5b51962-0391-52a9-87d4-18bb94158d90/scratchpad/rfc/rfc8349.txt (March 2018, obsoletes 8022; 3843 compact lines, read in full).

## Purpose
Core routing framework: three modules + one submodule. `ietf-routing` (prefix rt) defines
the generic components — `routing` container with `router-id`, read-only `interfaces`
list, `control-plane-protocols` (instances keyed by `type name`, with `static-routes`
container for the `static` pseudo-protocol), `ribs` (RIB list with `routes`, `active-route`
action). `ietf-ipv4-unicast-routing` (v4ur) and `ietf-ipv6-unicast-routing` (v6ur) augment
with `destination-prefix`, `next-hop-address`, static route lists; the submodule
`ietf-ipv6-router-advertisements` augments `ietf-ip`'s `ipv6` with RA parameters
(RFC 4861 §6.2.1). Obsolete `/routing-state` kept for non-NMDA.

## Design rules (sections 4–6)
- **System-controlled vs user-controlled list entries** (4.1): a RIB list must have at
  least one entry; the system creates it in `<operational>` ("ipv4-master",
  "ipv6-master"); a client may add config with the same key to *supplement* a
  system-controlled entry (deleting it removes only the extra config), or add new keys
  (user-controlled; feature `multiple-ribs`).
- Routes (5.1): minimum attributes `destination-prefix` (mandatory, added per AF),
  `route-preference` (administrative distance, lower better), `next-hop`.
- RIBs (5.2): one AF each (`address-family` identityref base `rt:address-family`, mandatory);
  exactly one default RIB per AF (`default-rib`, with `multiple-ribs`); contents managed by
  control-plane protocols; `active-route` action.
- Control-plane protocol (5.3): `type` identityref base `rt:control-plane-protocol`;
  pseudo-protocols `direct` (exactly one instance MUST exist; source of connected routes
  from interface addresses) and `static` (zero or more instances). New protocols: new
  identity (base `rt:control-plane-protocol` or derived), augment `route` with attributes
  (grouping), augment `control-plane-protocol` with a presence container conditional via
  `when "derived-from-or-self(rt:type, 'x:proto')"` (Appendix C RIP example).
- RA parameters (5.4): send-advertisements, max/min-rtr-adv-interval, managed-flag,
  other-config-flag, link-mtu, reachable-time, retrans-timer, cur-hop-limit,
  default-lifetime, prefix-list[prefix-spec]{valid-lifetime, on-link-flag,
  preferred-lifetime, autonomous-flag | no-advertise}; constant lifetimes (not
  decrementing). IsRouter = `ip:forwarding`.
- Interactions (6): `if:enabled=false` disables all routing on the interface;
  `ip:ipv4/enabled` and `ip:ipv4/forwarding` (same for v6) control participation; configured
  addresses MUST immediately create direct routes.
- Appendix B minimum implementation: no `multiple-ribs`, one system RIB per AF, `direct` +
  configurable `static`; hosts may remove RA sending via deviation.

## Module details worth keeping
- `ietf-routing@2018-03-13`: features `multiple-ribs`, `router-id`; identities
  `address-family` → `ipv4`, `ipv6`; `control-plane-protocol` → `routing-protocol` →
  `direct`, `static`; typedef `route-preference` uint32; groupings `address-family`
  (mandatory leaf), `router-id` (dotted-quad), `special-next-hop` enum
  blackhole|unreachable|prohibit|receive, `next-hop-content` (choice `next-hop-options`
  mandatory: simple-next-hop{outgoing-interface}, special-next-hop, next-hop-list{next-hop*
  [index]{index string, outgoing-interface}}), `next-hop-state-content` (same but
  `next-hop*` keyless), `route-metadata` (source-protocol identityref base routing-protocol
  mandatory, active empty, last-updated date-and-time). `static-routes` container has
  `when "derived-from-or-self(../type, 'rt:static')"`. `rib/address-family` `uses
  address-family` → **mandatory**; `default-rib` config false default true.
- `ietf-ipv4-unicast-routing@2018-03-13`: identity `ipv4-unicast` base `rt:ipv4`; augments
  with `when "derived-from-or-self(../../rt:address-family, 'v4ur:ipv4-unicast')"` at the
  right depth (`../../`, `../../../`, `../../../../../`); static `route[destination-prefix]`
  with `destination-prefix` mandatory, `description`, `next-hop` uses `rt:next-hop-content`
  with **augment inside uses** (`augment "next-hop-options/simple-next-hop" { leaf
  next-hop-address }`) — a `uses`-scoped augment the parser must support (7950 §7.13.2).
- `ietf-ipv6-unicast-routing@2018-03-13` mirrors v4; `include ietf-ipv6-router-advertisements
  { revision-date 2018-03-13; }` — a **submodule** (`belongs-to`), the parser must support
  include.
- RA submodule: `min-rtr-adv-interval` range 3..1350 with `must ". <= 0.75 *
  ../max-rtr-adv-interval"` (XPath arithmetic!), `max-rtr-adv-interval` 4..65535 default 600,
  `reachable-time` 0..3600000 ms default 0, `retrans-timer` default 0, `link-mtu` default 0,
  `default-lifetime` 0..65535 (MUST be 0 or in [max-rtr-adv-interval, 9000] — text only),
  `cur-hop-limit` no default (IANA TTL 64), `prefix/control-adv-prefixes` choice **with
  `default "advertise"`** (a choice default — parser/validator feature), `valid-lifetime`
  default 2592000, `preferred-lifetime` default 604800 with `must ". <= ../valid-lifetime"`,
  `on-link-flag`/`autonomous-flag` default true.
- Appendix D JSON instance: ribs `ipv4-master`/`ipv6-master`, static protocol `st0`, routes
  with `source-protocol: "ietf-routing:direct"`, `route-preference` 0 (direct) / 5 (static);
  shows module-qualified names where module changes (`"ietf-ipv4-unicast-routing:
  destination-prefix"` inside `route`).
- Security: `active-route` action discloses topology.

Notes:
- The kernel FIB is the *FIB*, not a full RIB: with FRR/bird installed the real RIB lives
  in the daemon (`vtysh -c 'show ip route json'`). A minimum implementation (Appendix B)
  reports the kernel table as the RIB, which is honest for static-only hosts.
- Multiple FIBs (`setfib`, `ifconfig fib`, `net.fibs`, `net.add_addr_allfibs`): best modelled
  as RFC 8529 network instances with `ietf-routing` mounted (see rfc8529.md), so at the host
  root `multiple-ribs` is off and `ribs` has exactly two system-controlled entries.
- Direct routes: when the agent applies an `ietf-ip` address, the kernel creates the
  connected route (`RTF_PINNED`, FreeBSD 12+) — satisfying 6.2 automatically.
- Event sources for YANG-Push on-change: rtsock `RTM_ADD/RTM_DELETE/RTM_CHANGE` per FIB
  (a `PF_ROUTE` socket sees only its own FIB unless `net.route.rtsock_...`? use `setsockopt
  SO_SETFIB` per socket, one socket per FIB, or netlink `RTNLGRP_IPV4_ROUTE` /
  `RTNLGRP_IPV6_ROUTE` which carry `RTA_TABLE`).
- Validation hot spots for the generator/validator: `when derived-from-or-self()` on
  augments (needs identity derivation at runtime), `uses`-scoped `augment`, `include` of a
  submodule, `choice ... default`, `must` with arithmetic (`0.75 * ../x`) → the XPath
  evaluator needs numbers, comparison, `*`, `..`, `current()`, `derived-from-or-self()`.
- SIDs: no IANA .sid for ietf-routing yet (RFC 9595 Table 4 lists only coreconf, yang-types,
  inet-types, iana-crypt-hash, netconf-acm, sid-file, interfaces, ip, system, iana-if-type);
  Arcana must generate `.sid` files for ietf-routing/v4ur/v6ur in its own range (private
  mega-range or experimental 60000–99999 for development only).
