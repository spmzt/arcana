# RFC 8344 — A YANG Data Model for IP Management (ietf-ip, NMDA)

Source: /tmp/claude-0/-home-user-arcana/c5b51962-0391-52a9-87d4-18bb94158d90/scratchpad/rfc/rfc8344.txt (March 2018, obsoletes 7277; 1528 compact lines, read in full).

## Purpose
Augments `/if:interfaces/if:interface` with per-interface IPv4 and IPv6 parameters:
address-family enable, forwarding, MTU, addresses (config + learned, with origin/status),
neighbor cache (static entries in config; ARP/ND cache in operational), IPv6 DAD and SLAAC
knobs. Deprecated copies under `/if:interfaces-state/if:interface` for non-NMDA servers.

## Tree (section 2) verbatim
```
module: ietf-ip
  augment /if:interfaces/if:interface:
    +--rw ipv4!
    |  +--rw enabled?      boolean
    |  +--rw forwarding?   boolean
    |  +--rw mtu?          uint16
    |  +--rw address* [ip]
    |  |  +--rw ip               inet:ipv4-address-no-zone
    |  |  +--rw (subnet)
    |  |  |  +--:(prefix-length)
    |  |  |  |  +--rw prefix-length?   uint8
    |  |  |  +--:(netmask)
    |  |  |     +--rw netmask?         yang:dotted-quad
    |  |  |             {ipv4-non-contiguous-netmasks}?
    |  |  +--ro origin?          ip-address-origin
    |  +--rw neighbor* [ip]
    |     +--rw ip                    inet:ipv4-address-no-zone
    |     +--rw link-layer-address    yang:phys-address
    |     +--ro origin?               neighbor-origin
    +--rw ipv6!
       +--rw enabled?                     boolean
       +--rw forwarding?                  boolean
       +--rw mtu?                         uint32
       +--rw address* [ip]
       |  +--rw ip               inet:ipv6-address-no-zone
       |  +--rw prefix-length    uint8
       |  +--ro origin?          ip-address-origin
       |  +--ro status?          enumeration
       +--rw neighbor* [ip]
       |  +--rw ip                    inet:ipv6-address-no-zone
       |  +--rw link-layer-address    yang:phys-address
       |  +--ro origin?               neighbor-origin
       |  +--ro is-router?            empty
       |  +--ro state?                enumeration
       +--rw dup-addr-detect-transmits?   uint32
       +--rw autoconf
          +--rw create-global-addresses?        boolean
          +--rw create-temporary-addresses?     boolean
          |       {ipv6-privacy-autoconf}?
          +--rw temporary-valid-lifetime?       uint32
          |       {ipv6-privacy-autoconf}?
          +--rw temporary-preferred-lifetime?   uint32
                  {ipv6-privacy-autoconf}?
```
Module `ietf-ip@2018-02-22`, yang-version 1.1, prefix `ip`, imports if, inet, yang.
Features: `ipv4-non-contiguous-netmasks`, `ipv6-privacy-autoconf`.
Typedefs: `ip-address-origin` enum other|static|dhcp|link-layer|random;
`neighbor-origin` enum other|static|dynamic.
Details: `ipv4`/`ipv6` are **presence containers** ("Enables IPvX unless enabled=false");
`enabled` default true; `forwarding` default false; ipv4 `mtu` uint16 range 68..max,
ipv6 `mtu` uint32 range 1280..max, units octets; ipv4 `address/subnet` choice mandatory
(`prefix-length` 0..32 | `netmask` dotted-quad with feature); ipv6 `prefix-length` 0..128
mandatory; `neighbor/link-layer-address` mandatory (but "not instantiated" in operational
when ipv6 `state` = incomplete — a documented NMDA violation allowed by 8342 §5.3);
ipv6 `address/status` enum preferred|deprecated|invalid|inaccessible|unknown|tentative|
duplicate|optimistic; ipv6 `neighbor/state` enum incomplete|reachable|stale|delay|probe;
`dup-addr-detect-transmits` default 1; `autoconf/create-global-addresses` default true,
`create-temporary-addresses` default false, `temporary-valid-lifetime` default 604800 s,
`temporary-preferred-lifetime` default 86400 s. Deprecated `/interfaces-state` versions of
both containers (config false, no `enabled`, no `autoconf`, no DAD).
IP-MIB mapping: ipv4↔ipv4InterfaceEnableStatus, address↔ipAddressEntry, neighbor↔
ipNetToPhysicalEntry, origin↔ipAddressOrigin/ipNetToPhysicalType, status↔ipAddressStatus,
state↔ipNetToPhysicalState, ipv6/forwarding↔ipv6InterfaceForwarding.
SID range (RFC 9595 Table 4): ietf-ip 1600, size 100.
Appendix B example uses origins `or:default` (enabled, forwarding), `or:system` (mtu 1500),
`or:learned` (neighbors, DHCP address).

## FreeBSD mapping, node by node
| Node | Operational source | Config sink (running = rc.conf; intended applied via ioctl) |
|---|---|---|
| `ipv4!` presence | any `AF_INET` ifaddr present, or `IFF_UP` with inet capability | `ifconfig_<if>="inet ..."` presence; absence of container → remove all inet addrs (`SIOCDIFADDR`) |
| `ipv4/enabled` | true if the stack is attached (always for FreeBSD ifs; false only if agent models `ifconfig <if> -inet`? no such knob — report `true`, origin `default`) | deviate `not-supported` or accept only `true` |
| `ipv4/forwarding` | per-interface forwarding does not exist; global `sysctl net.inet.ip.forwarding`; report global value with origin `system` | `gateway_enable="YES"` in rc.conf ↔ `net.inet.ip.forwarding=1`; a `must` or description note that all interfaces share the value; alternative: `arcana-ip` deviation to make it global |
| `ipv4/mtu` | `SIOCGIFMTU` `ifr_mtu` (link MTU; FreeBSD has no per-AF MTU) | `SIOCSIFMTU`; rc.conf `ifconfig_<if>="... mtu 9000"` |
| `ipv4/address[ip]` | `getifaddrs` `AF_INET` (`ifa_addr`, `ifa_netmask`, `ifa_broadaddr`/`ifa_dstaddr`); netlink `RTM_GETADDR` `IFA_LOCAL`/`IFA_ADDRESS` | `SIOCAIFADDR` (`struct in_aliasreq`) / `SIOCDIFADDR`; rc.conf `ifconfig_<if>="inet A/P"`, `ifconfig_<if>_alias0="inet B/P"`; Arcana already implements this as address live/persistent |
| `prefix-length` | popcount of `ifa_netmask` (contiguous); `IFA_PREFIXLEN`? (`ifa_prefixlen` in netlink `ifaddrmsg`) | mask = prefix |
| `netmask` {non-contiguous} | FreeBSD accepts non-contiguous masks in `SIOCAIFADDR` → may advertise the feature, but routing code assumes contiguous; do not advertise | — |
| `address/origin` | `static` if present in rc.conf; `dhcp` if `dhclient`/`dhcpcd` lease (check `/var/db/dhclient.leases.<if>` or `SYNCDHCP` in `ifconfig_<if>`); `random` for 169.254/16 (none in base); `other` for CARP/VIP | — |
| `ipv4/neighbor[ip]` | ARP table: `sysctl` `NET_RT_FLAGS` `RTF_LLINFO` via `sysctl(CTL_NET, PF_ROUTE, 0, AF_INET, NET_RT_FLAGS, RTF_LLINFO)` (what `arp -an` does), or netlink `RTM_GETNEIGH`; `arp -an --libxo json` | static: `arp -S ip mac` (`RTM_ADD` with `RTF_LLDATA`/`RTF_STATIC`, netlink `RTM_NEWNEIGH` `NUD_PERMANENT`); rc.conf `static_arp_pairs="pair1"` + `static_arp_pair1="ip mac"` |
| `neighbor/link-layer-address` | `sdl` from the rtentry; LLADDR | key of static entry |
| `neighbor/origin` | `RTF_STATIC` → static; else dynamic (ARP) | — |
| `ipv6!` presence | `AF_INET6` ifaddr present or `ND6_IFF_IFDISABLED` clear | rc.conf `ifconfig_<if>_ipv6=` presence; `ipv6_activate_all_interfaces` |
| `ipv6/enabled` | `!(nd6 flags & ND6_IFF_IFDISABLED)` via `SIOCGIFINFO_IN6` (`struct in6_ndireq.ndi.flags`), what `ifconfig <if> inet6 ifdisabled` toggles | `SIOCSIFINFO_IN6` with `ND6_IFF_IFDISABLED`; rc.conf `ifconfig_<if>_ipv6="inet6 ifdisabled"` / `ipv6_activate_all_interfaces="YES"` |
| `ipv6/forwarding` | global `net.inet6.ip6.forwarding`; report as system | `ipv6_gateway_enable="YES"` |
| `ipv6/mtu` | `SIOCGIFMTU` or ND6 `ndi.linkmtu`/`maxmtu` (`SIOCGIFINFO_IN6`) | `SIOCSIFMTU` (shared with v4) |
| `ipv6/address[ip]` | `getifaddrs` `AF_INET6`; `SIOCGIFAFLAG_IN6` for flags; `SIOCGIFALIFETIME_IN6` for lifetimes; netlink `RTM_GETADDR` with `IFA_FLAGS`, `IFA_CACHEINFO` | `SIOCAIFADDR_IN6` (`struct in6_aliasreq`) / `SIOCDIFADDR_IN6`; rc.conf `ifconfig_<if>_ipv6="inet6 A/P"`, `ifconfig_<if>_alias0="inet6 B/P"` |
| `prefix-length` | `ifa_netmask` popcount, `in6_prefixlen` | — |
| `address/origin` | `IN6_IFF_AUTOCONF` → `link-layer` (EUI-64) or `random` (`IN6_IFF_TEMPORARY`, or stable-privacy `net.inet6.ip6.use_stableaddr`), `rtsol`/`dhcp6` → `dhcp` for DHCPv6 (ports), configured → `static`, link-local fe80:: → `link-layer`/`other` | — |
| `address/status` | `IN6_IFF_TENTATIVE`→tentative, `IN6_IFF_DUPLICATED`→duplicate, `IN6_IFF_DEPRECATED`→deprecated, `IN6_IFF_DETACHED`→inaccessible, `IN6_IFF_OPTIMISTIC`? (not in FreeBSD) , interface down→inaccessible, else preferred; lifetime expired→invalid | — |
| `ipv6/neighbor[ip]` | `ndp -an` (`sysctl NET_RT_FLAGS RTF_LLINFO AF_INET6`), netlink `RTM_GETNEIGH` AF_INET6; `ndp -an --libxo json` not available (ndp lacks libxo) — use the sysctl | static: `ndp -s ip mac` / `RTM_ADD`; rc.conf `static_ndp_pairs` |
| `neighbor/link-layer-address` | sdl; absent if `incomplete` | mandatory in static entry |
| `neighbor/origin` | `RTF_STATIC`→static else dynamic | — |
| `neighbor/is-router` | `ND6_LLINFO_... ` `ln_router` flag: rtm flag `RTF_GATEWAY`? no — `ndp` prints `R` from `sin6` `ND6_LLINFO` `ln_router`; via `sysctl` it is in `rt_msghdr`? ndp uses `rtm->rtm_flags & RTF_GATEWAY` → "R". Netlink `NTF_ROUTER` | — |
| `neighbor/state` | `ND6_LLINFO_INCOMPLETE/REACHABLE/STALE/DELAY/PROBE` (ndp's `N/R/S/D/P`), `NUD_*` via netlink | — |
| `dup-addr-detect-transmits` | `sysctl net.inet6.ip6.dad_count` (global, not per-interface) → origin `system` | `net.inet6.ip6.dad_count` in sysctl.conf (global; or `ifconfig inet6 no_dad` per-interface = 0) |
| `autoconf/create-global-addresses` | `ND6_IFF_ACCEPT_RTADV` (`ifconfig inet6 accept_rtadv`) ∧ `net.inet6.ip6.accept_rtadv`? | `ifconfig_<if>_ipv6="inet6 accept_rtadv"`, `rtsold_enable` |
| `create-temporary-addresses` {privacy} | `net.inet6.ip6.use_tempaddr` (global) | sysctl.conf `net.inet6.ip6.use_tempaddr=1`, `prefer_tempaddr` |
| `temporary-valid-lifetime` | `net.inet6.ip6.temppltime`? no: `net.inet6.ip6.tempvltime` | sysctl |
| `temporary-preferred-lifetime` | `net.inet6.ip6.temppltime` | sysctl |

Notes:
- FreeBSD has many *global* knobs where the model is per-interface (forwarding, DAD count,
  temporary addresses). Options: (1) report the global value on every interface with origin
  `system` and reject per-interface writes that differ from the global (`invalid-value` or
  `operation-not-supported`); (2) YANG `deviation` statements in an `arcana-ip-deviations`
  module (`deviate not-supported` for `forwarding`, with a new `arcana-system:forwarding`
  leaf). RFC 7950 §7.20.3 deviations are the honest way; the generator must support them.
- Jails (non-VNET): the jail's `ip4.addr` list manifests as aliases on host interfaces;
  the agent can annotate with an `arcana-jails:owner` augment; the jail itself cannot have
  an `ietf-ip` instance (it has no interfaces). VNET jails: full `ietf-ip` under the LNE
  mount (RFC 8530).
- Event sources: rtsock `RTM_NEWADDR`/`RTM_DELADDR`/`RTM_NEWMADDR`, `RTM_ADD/DELETE` with
  `RTF_LLINFO` for neighbors; netlink `RTNLGRP_IPV4_IFADDR`, `RTNLGRP_IPV6_IFADDR`,
  `RTNLGRP_NEIGH`.
- Existing Arcana code: `address live` = `SIOCAIFADDR` now (operational/dynamic),
  `address persistent` = rc.conf edit (running). In NMDA terms: edit `running` → agent
  applies to intended → operational shows it with origin `intended`; `address live` without
  persistence is a write to a *dynamic configuration datastore* (RFC 8342 §5.2) — the
  design doc proposes `arcana-ds:live` as such a datastore identity.
