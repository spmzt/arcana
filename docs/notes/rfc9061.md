# RFC 9061 — A YANG Data Model for IPsec Flow Protection Based on SDN

Source: /tmp/claude-0/-home-user-arcana/c5b51962-0391-52a9-87d4-18bb94158d90/scratchpad/rfc/rfc9061.txt (read in full, 4502 lines).
Status: Standards Track, I2NSF WG, July 2021.

## 1. Purpose and where it sits

- Lets an **I2NSF Controller** (SDN controller; Arcana console) configure and monitor IPsec SAs on
  **flow-based NSFs** (hosts or gateways; Arcana agents) over the **NSF-Facing Interface**. It is a
  device-facing model (the controller writes the device's IPsec databases); the user-facing
  "flow protection policy" (Consumer-Facing Interface) is out of scope.
- Two cases, two modules plus a common one:
  - **IKE case** (`ietf-i2nsf-ike`): the NSF runs IKEv2; the controller provisions PAD (identities,
    credentials), IKE connection parameters, SPD (policies) and child SA parameters; IKEv2 does SA
    establishment and rekey. State data: IKE SA details and counts.
  - **IKE-less case** (`ietf-i2nsf-ikeless`): the NSF has only SPD and SAD; the controller does what
    IKEv2 would (SPI choice, key generation, rekey on `sadb-expire`, reactive SA creation on
    `sadb-acquire`, NAT detection), and the NSF emits PF_KEYv2-style notifications.
  - `ietf-i2nsf-ikec`: shared typedefs and groupings (algorithms as IANA IKEv2 transform IDs,
    mode, encapsulation, lifetime, port-range, traffic selector, tunnel, policy grouping).
- Scenarios: gateway-to-gateway and host-to-host; host-to-gateway (roaming) is out of scope.
- Section 4 trade-offs: IKE case is easier to deploy and more secure (NSFs make their own session
  keys); IKE-less suits constrained NSFs and avoids inter-NSF IKE at the cost of controller
  complexity, latency, and controller-held keys. NAT: IKE-less requires the controller to know about
  NAT, else the IKE case MUST be used. State loss (Section 4.2): the controller re-pushes config;
  startup datastore may keep IKE config persistent; the default policy MUST be DISCARD (plus ALLOW
  for controller traffic) preconfigured in startup before the NSF contacts the controller.
- Security considerations: credentials/keys are write-only (NACM default-deny-all on
  pre-shared/secret, digital-signature/private-key, esp-sa keys and IV); the controller MUST NOT
  store keys after distribution; the controller-NSF channel must be at least as strong as the SAs it
  configures and provide forward secrecy if the SAs are meant to.
- Fit with Arcana: Arcana already has both halves in embryo — luxuria/ipsec.c (strongSwan via
  swanctl.conf files in conf.d, IKEv2 only, ECDSA P-256 host keys, pubkey trust, tunnel or
  transport children, `reqid` for ipsec(4) interfaces with `policies = no`) is the IKE case;
  invidia/sa.c (setkey(8) manual SAs on ipsec(4) interfaces, HKDF-SHA256-derived keys from an X25519
  agreement, AES-GCM-16, ESN, `-r 128`, `-natt src[4500] dst[4500]`, three-step rotation) is an
  IKE-less data plane with a controller-side key exchange like [IPSECME-CONTROLLER-IKE].

### 2.1 ietf-i2nsf-ikec, exactly

Typedefs:
- `encr-alg-t` uint16: IANA IKEv2 Transform Type 1 (Encryption) ID. `intr-alg-t` uint16: Transform
  Type 3 (Integrity) ID. Both "MUST follow the requirement levels" of RFC 8221/8247.
- `ipsec-mode` enum {transport (no NAT support), tunnel}.
- `esp-encap` enum {espintcp (RFC 8229), espinudp (RFC 3948), none}.
- `ipsec-protocol-params` enum {esp} (only ESP; extensible).
- `lifetime-action` enum {terminate-clear, terminate-hold, replace}.
- `ipsec-traffic-direction` enum {inbound, outbound}.
- `ipsec-spd-action` enum {protect, bypass, discard}.
- `ipsec-inner-protocol` union {uint8; enum {any = 256}} default any.

Groupings:
- `encap`: espencap (default none), sport (default 4500), dport (default 4500), oaddr* inet:ip-address.
- `lifetime`: time uint32 s (0 = infinite), bytes uint64, packets uint32, idle uint32 s; all default 0.
- `port-range`: start, end (must '. >= ../start'); single port = start == end.
- `tunnel-grouping`: local, remote (inet:ip-address, mandatory), df-bit enum {clear (default), set,
  copy} (ignored for IPv6), bypass-dscp boolean default true, list dscp-mapping [id] (must
  '../bypass-dscp = "false"', ordered-by user) {id uint8, inner-dscp? (absent = ANY), outer-dscp
  default 0}.
- `selector-grouping`: local-prefix, remote-prefix (inet:ip-prefix, mandatory), inner-protocol
  default any, list local-ports [start end], list remote-ports [start end] (ICMP: the 16-bit value
  is type and code; absent list = port 0..0 = any).
- `ipsec-policy-grouping`: anti-replay-window-size uint32 default 64; container traffic-selector
  (uses selector-grouping); container processing-info { action default discard; container
  ipsec-sa-cfg (when action = protect) { pfp-flag default false; ext-seq-num default false;
  seq-overflow default false (MUST be false with AEAD); stateful-frag-check default false; mode
  default transport; protocol-parameters default esp; container esp-algorithms (when esp) {
  leaf-list integrity intr-alg-t default 0 ordered-by user; list encryption [id] ordered-by user {id
  uint16, algorithm-type default 20 (ENCR_AES_GCM_16), key-length default 128}; tfc-pad default
  false }; container tunnel (when mode = tunnel) uses tunnel-grouping } }.

### 2.2 ietf-i2nsf-ike specifics

Typedefs: `ike-spi` uint64; `autostartup-type` enum {add, on-demand, start}; `fs-group` uint16 (DH
Transform Type 4 ID); `auth-protocol-type` enum {ikev2 = 2}; `auth-method-type` enum {pre-shared,
eap, digital-signature, null}.
Notable statements: `choice identity { mandatory true; }` with cases ipv4-address, ipv6-address,
fqdn-string, rfc822-address-string, dnx509 (binary DER DN), gnx509 (binary DER GeneralName), id-key
(binary), id-null (empty); `container eap-method { when "../auth-method = 'eap'"; leaf eap-type
uint32 range 1..4294967295 mandatory }` (tree says uint64 — a tree/module mismatch in the RFC);
`container pre-shared { when "../auth-method[.='pre-shared' or .='eap']"; leaf secret
{nacm:default-deny-all; yang:hex-string} }`; `container digital-signature { when
"../auth-method[.='digital-signature' or .='eap']"; ds-algorithm uint8 default 14; choice
public-key {raw-public-key | cert-data}; private-key {nacm:default-deny-all}; ca-data*; crl-data;
crl-uri; oscp-uri (sic) }`; conn-entry: `list ike-sa-encr-alg { min-elements 1; }`; `leaf-list
ike-sa-intr-alg default 12`; `dh-group default 14`; `container fragmentation { leaf mtu { when
"../enabled='true'"; range 68..65535 } }`; `container local { leaf local-pad-entry-name string
mandatory }` ("MUST match a pad-entry-name" — prose, not a leafref); `container state { config
false; }`; `container number-ike-sas { config false; }` with yang:gauge64.

### 2.3 ietf-i2nsf-ikeless specifics

`feature ikeless-notification` gates the four notifications. `spd-entry`: `direction` mandatory,
`reqid` uint64 default 0; `sad-entry`: `reqid`, `ipsec-sa-config { spi uint32 mandatory;
ext-seq-num default **true** (differs from the SPD default false); seq-overflow default false;
anti-replay-window-size default 64; traffic-selector; protocol-parameters default esp; mode default
transport; container esp-sa (when esp) { encryption { encryption-algorithm default 12
(ENCR_AES_CBC), key hex-string nacm:default-deny-all, iv hex-string nacm:default-deny-all };
integrity { integrity-algorithm default 12 (AUTH_HMAC_SHA2_256_128), key } }; sa-lifetime-hard;
sa-lifetime-soft { uses lifetime; action lifetime-action (no default) }; container tunnel (when
tunnel) { uses tunnel-grouping; leaf-list dscp-values inet:dscp }; encapsulation-type }`;
`ipsec-sa-state { config false; sa-lifetime-current; replay-stats { replay-window {w, t, b};
packet-dropped counter64; failed counter64; seq-number-counter uint64 } }`.
Notifications: `sadb-acquire {ipsec-policy-name mandatory; traffic-selector}`, `sadb-expire
{ipsec-sa-name mandatory; soft-lifetime-expire default true; lifetime-current}`,
`sadb-seq-overflow {ipsec-sa-name mandatory}`, `sadb-bad-spi {spi uint32 mandatory}`.

## 3. Node-by-node meaning and candidate FreeBSD realisation

### 3.1 IKE case -> strongSwan (swanctl.conf / VICI)

Arcana writes `conf.d/arcana-<name>.conf` and runs `swanctl --load-all`; VICI (libvici, or the
`vici` socket protocol) would allow the same without files (`load-conn`, `load-key`, `load-shared`,
`load-cert`, `initiate`, `terminate`, `list-sas`, `stats`, and the events `ike-updown`,
`child-updown`, `ike-rekey`, `child-rekey`) and is the better long-term NSF-facing path because
state (`list-sas`) and events arrive structured. Algorithm IDs (IANA) -> strongSwan proposal tokens:

| IANA encr (Type 1) | strongSwan | FreeBSD kernel (setkey name) |
|---|---|---|
| 3 ENCR_3DES | 3des | 3des-cbc |
| 11 ENCR_NULL | null | null |
| 12 ENCR_AES_CBC (key 128/192/256) | aes128 / aes192 / aes256 | aes-cbc (key length decides) |
| 13 ENCR_AES_CTR | aes128ctr … | aes-ctr |
| 18/19/20 ENCR_AES_GCM_8/12/16 | aes128gcm8/12/16 … | aes-gcm-8 / aes-gcm-12 / aes-gcm-16 (FreeBSD 13+ for 8/12) |
| 23 ENCR_CAMELLIA_CBC | camellia128 … | camellia-cbc |
| 28 ENCR_CHACHA20_POLY1305 | chacha20poly1305 | chacha20-poly1305 (FreeBSD 13+) |
| 14-16 AES-CCM | aes128ccm8… | not in FreeBSD netipsec |

| IANA integ (Type 3) | strongSwan | setkey |
|---|---|---|
| 0 NONE | (omit; AEAD) | (omit -A) |
| 1 AUTH_HMAC_MD5_96 | md5 | hmac-md5 |

### 3.2 IKE-less case -> PF_KEYv2 / setkey(8)

The right realisation is for arcana-agent to speak **PF_KEYv2 directly** (socket(PF_KEY, SOCK_RAW,
PF_KEY_V2); libipsec's pfkey_* helpers): SADB_ADD/UPDATE/DELETE/GET/DUMP for the SAD,
SADB_X_SPDADD/SPDDELETE/SPDDUMP for the SPD, SADB_REGISTER to receive SADB_ACQUIRE, and reading
SADB_EXPIRE. setkey(8) is the same thing through a text file, which is what sa.c does today
(`add src dst esp SPI -m tunnel -u reqid -r 128 [-esn] [-natt src[4500] dst[4500]] -E alg 0xkey
[-A alg 0xkey] ;`). Both are listed.

## 5. Features and what Arcana could advertise

Only one feature exists: `ikeless-notification` ("the NSF is expected to implement this feature"
for the IKE-less case). Arcana can advertise it with a documented subset: sadb-acquire and
sadb-expire exact (PF_KEY), sadb-seq-overflow synthesised, sadb-bad-spi absent (or approximate
with a global counter event). The IKE module has no features; capability discovery (Section 4.4:
cryptographic suites, auth methods, IKE vs IKE-less support) is out of the RFC's scope and must be
an Arcana `dump` (e.g. `ipsec-capabilities`: algorithms from `sysctl net.inet.ipsec` / `kldstat`
crypto, strongSwan plugin list from `swanctl --list-algs`).

## 7. Open decisions and trade-offs

1. **IKE case transport: swanctl.conf files vs VICI.** Files (current) are simple, persistent across
   reboots (Section 4.2 startup datastore) and auditable; VICI gives structured `list-sas`, events
   for state changes, and no filesystem dance, but config is then not persistent unless Arcana also
   writes files. Likely: keep files as the persisted "startup datastore", use VICI for state/events.
2. **IKE-less transport: setkey(8) text vs native PF_KEY.** Text is what exists; PF_KEY in-process
   gives SADB_ACQUIRE/EXPIRE delivery (needed for the notifications), structured SADB_DUMP for state,
   and avoids writing keys to files (even 0600, Section 7.2 wants keys never persisted). Recommend
   PF_KEY with libipsec.
3. **Where the SPD lives: setkey spdadd vs ipsec(4) interfaces.** RFC 9061 is policy-based; Arcana's
   SD-WAN is route-based (ipsec(4) + FIBs). Both can be modelled: a `tunnel` SPD entry with reqid R
   can be realised as `ipsecN reqid R tunnel local remote` + routes, or as literal spdadd. Decide the
   default and expose which is used; selectors with ports force spdadd.
4. **Who holds the private key (IKE case).** RFC allows controller-generated private keys; Arcana's
   stance (host-generated ECDSA keys, public half exported) is the safer choice the RFC explicitly
   permits ("the NSF MAY generate the private key"). Reject private-key writes or accept them only
   for imported certificates.
5. **IKE-less key handling in the console.** RFC: controller MUST NOT store keys after distribution
   — Arcana derives keys per epoch from X25519 agreements (controller holds public halves only, the
   agreement is done on the hosts). That is closer to Controller-IKE than to RFC 9061's "controller
   generates keys" and is stronger; the model's `esp-sa/key` would then be filled by the agent, not
   the console: decide whether the family carries keys at all (an Arcana `derive` operation instead
   of literal keys), or supports both (literal keys for interop).
6. **Rekey orchestration.** Appendix D.2 (inbound both, outbound both, delete old) matches Arcana's
   in/out/commit; the console must handle partial failures with rollback as the appendix MUSTs.
   `net.key.preferred_oldsa` must be 0 for new outbound SAs to take over.
7. **Notification coverage.** sadb-bad-spi cannot be produced; options: omit (do not advertise),
   emit a periodic global-counter-based event, or carry a FreeBSD kernel patch (PF_KEY notification on
   unknown SPI). Decide and document.
8. **Algorithm identity representation.** RFC uses IANA numbers (uint16); the console UI needs names
   (strongSwan tokens, setkey names). Keep numbers on the wire (interoperable), names in the console.
9. **Lifetime semantics.** FreeBSD enforces time and bytes only; declare packets/idle unsupported
   (reject non-zero) or have the agent enforce them in userland by polling `allocations`/`usetime`
   and deleting the SA (feasible: agent-side timers).
10. **Replay window.** Default 64 per RFC; Arcana learned ESN needs an explicit window and uses 128;
    pick 128 or follow the model's value; windows > 255 need SADB_X_EXT_SA_REPLAY (FreeBSD 13+).
11. **Two families or one.** Mirror the RFC (ike and ikeless as separate cblink families sharing an
    `ikec` library spec) vs one `ipsec` family; the RFC 9348 augments target both, so two families
    with shared sets is the cleaner mirror.
