(scratchpad/rfc/iana-icmpv4-types.yang, iana-icmpv6-types.yang, iana-ipv6-ext-types.yang,

## 1. Purpose and where it sits

- Fixes the limitations of RFC 8519 listed in Appendix A: no lists of prefixes (A.1), no aliases or
  defined sets (A.2), ACLs bound only to interfaces (A.3), partial fragment handling (A.4),
  TCP flags without bitmask/operators as in BGP Flow Spec (A.5), no rate-limit action (A.6),
  no payload matching (A.7), no reuse of ACL content across devices (A.8), no MPLS matching (A.9).
- It is still a **device model** structurally (every node augments `/acl:acls`), but it is written so
  that ACLs and defined sets "may be defined at the network/administrative domain level and
  associated to devices" (Section 1): the console holds the defined sets and ACLs, the agent receives
  them. The RFC does *not* define a network-level module, nor any new attachment point: **the
  published module has no augmentation of `/acl:acls/acl:attachment-points`** (VRF, device-wide or
  "all interfaces" binding are only requirements in Appendix A.3/A.8). Those remain vendor augments.
- Adds: `defined-sets` (ipv4/ipv6 prefix sets, port sets, protocol sets, ICMPv4/ICMPv6 type sets,
  aliases), new match choices (`payload` pattern, `alias`, `mpls`), new L2 matches (`vlan-filter`,
  `isid-filter`), fragment handling (`ipv4-fragment`, `ipv6-fragment`), prefix-list/protocol-set
  references on ipv4/ipv6, `extension-header` on ipv6, `flags-bitmask` and port-set refs on tcp,
  port-set refs on udp, ICMP set refs on icmp, and actions `log-action`, `counter-action`,
  `rate-limit`.
- It creates three IANA-maintained modules: `iana-icmpv4-types`, `iana-icmpv6-types`,
  `iana-ipv6-ext-types`, each a `*-type-name` enumeration mirrored from the IANA registry plus a
  `*-type` union of uint8 and that enumeration.
- Note the explicit interop rules: clients supporting both `flags-bitmask` and RFC 8519 `flags` MUST
  NOT set both (enforced by `must 'not(../acl:flags)'`); same for `ipv4-fragment` vs `flags`.
- Module conforms to NMDA. Mentions DOTS (RFC 9132) and BGP Flow Spec (RFC 8955/8956) as the typical
  sources of such rules — relevant to Arcana's SD-WAN security policies (ip-block, rate-limit).

## 3. Node-by-node meaning and candidate FreeBSD realisation

### 3.1 defined-sets (augment /acl:acls; `nacm:default-deny-write`)

| Node | Meaning | FreeBSD realisation |
|---|---|---|
| ipv4-prefix-sets/prefix-set[name] {description, prefix* inet:ipv4-prefix} | Named list of IPv4 prefixes; match if address is in any. | `ipfw table <name> create type addr valtype legacy` + `ipfw table <name> add <prefix>` per prefix; referenced as `from table(<name>)` / `to table(<name>)`. Atomic replacement by building a shadow table and `ipfw table A swap B` — exactly what invidia/sdwan.c does today. Table names: up to 63 chars of `[A-Za-z0-9_.-]`, must not be all digits; `net.inet.ip.fw.tables_max` (default 128) bounds the number — raise it. IPv4 and IPv6 can share one addr table, but keep two to mirror the model. pf: `table <name> persist { ... }`. |
| ipv6-prefix-sets/prefix-set[name] {prefix* inet:ipv6-prefix} | Same for IPv6. | `type addr` table; IPv6 prefixes accepted. |
| port-sets/port-set[name]/port[id]/port-range-or-operator | Named set of ports; each entry is a range or an operator+port. | Two options. (a) Expand into the rule's port list: `dst-port 80,443,1000-2000` (ipfw limit: 30 entries per list; operators neq/lte/gte become `0-p`, `p-65535`, or `not`). (b) `ipfw table <name> create type number` with one entry per port and `lookup dst-port <name>` / `lookup src-port <name>` in the rule — exact for sets of single ports, but ranges must be enumerated (a 1000-port range = 1000 entries) and `neq` cannot be a table. Recommend (a) when total entries <= 30, (b) for large enumerable sets, error otherwise. pf has no port tables (port lists in a rule only). |
| protocol-sets/protocol-set[name]/protocol* union(uint8,string) | Named list of IP protocols by number or name. | ipfw or-block in the rule: `{ proto tcp or proto udp or proto 47 }`; names resolved through /etc/protocols (ipfw accepts names). No table type for protocols. pf: `proto { tcp udp 47 }`. |
| icmpv4-type-sets/set[name]/icmpv4-type[type] {type iana:icmpv4-type, code, rest-of-header} | Named set of ICMPv4 types (code/rest optional). | `icmptypes 3,8,11` list in the rule (names from the IANA enum translated to numbers). `code` and `rest-of-header` cannot be matched in ipfw (pf: `icmp-type t code c`). |
| icmpv6-type-sets/set[name]/icmpv6-type[type] | Same for ICMPv6. | `icmp6types 1,2,128` list. |
| aliases/alias[name] {vlan*, prefix* inet:ip-prefix, port-range*[lower-port]{lower-port, upper-port must >= lower}, protocol* uint8, fqdn* inet:domain-name, uri* inet:uri} | A composite object ("a set of HTTPS servers": prefixes + protocol 6 + port 443). Referenced from an ACE by `alias-name*`. | Decompose: prefix -> addr table `alias.<name>` (mixed v4/v6 table, `from/to table(...)`); port-range -> port list; protocol -> or-block; vlan -> see vlan-filter (only via `recv vlan<N>` interface names or bridge VLAN filtering); fqdn -> not a kernel match: resolve periodically (or from Unbound's cache / DNS filter that Arcana already runs) into the addr table — an SD-WAN "dns filter" style object; uri -> not a packet filter: hand to the Squid URL filter / c-icap that Arcana's SD-WAN security policy already drives. An alias with several members is an AND of its parameter classes (prefix AND port AND protocol), consistent with the HTTPS example. |

### 3.2 New match nodes

| Node | Meaning | ipfw / pf |
|---|---|---|
| matches/(payload)/pattern {match-on-payload} {offset identityref(layer2/layer3/layer4/payload), length uint16 (bytes to skip after offset), operator, pattern binary} | Match `pattern` at `offset + length` with operator (match/any/not). Example B.3: IPv6 proto 41, offset layer4, length 20, pattern "2001:db8::1" (inner dst of IP-in-IP). | ipfw cannot match packet bytes (no `u32`-style match). FreeBSD options: (1) `ipfw ... divert <port>` to Suricata (Arcana already runs IDS/IPS by divert) with a generated rule `content:"..."; offset:N; depth:M;` — Suricata's offset is relative to payload, so layer2/layer3/layer4 offsets need arithmetic per protocol; (2) `ipfw ... netgraph <cookie>` / `ngtee` to an ng_bpf(4) node with a compiled BPF program that implements offset/length/pattern at any layer (exact for layer2/3/4 given fixed header lengths; "payload" after variable TCP options needs BPF's `ldx 4*([14]&0xf)`-style indexing — expressible); (3) pf: no payload match. Recommend ng_bpf via ipfw `netgraph` action for exact semantics, or declare the feature unsupported initially. |
| matches/(alias)/alias-name* alias-ref | One or more aliases (OR between aliases, AND within). | Expand per alias as in 3.1; multiple aliases -> an or-block of table lookups when only prefixes differ, otherwise one rule per alias (same action). |
| matches/(mpls)/mpls-values {match-on-mpls} {traffic-class 0..7, label-position top/bottom, upper-label-range, lower-label-range (rt-types:mpls-label), label-block-name, ttl-value} | Match MPLS header fields. | FreeBSD has no MPLS data plane (no label switching in the kernel; netgraph has no MPLS node in base) and ipfw/pf have no MPLS matches. Cannot. |
| matches/l2/vlan-filter {match-on-vlan-filter} {frame-type string, (vlan-type) range lower-vlan..upper-vlan | operator + vlan*} | VLAN id range/operator filter (EVPN bridging). | ipfw: no VLAN-tag match; frames on a vlan(4) interface are seen as `recv vlan<N>`, so a VLAN set can be expressed as `{ recv vlan10 or recv vlan11 ... }` only where vlan interfaces exist; in the L2 pass `mac-type vlan` matches tagged frames but not the id. if_bridge VLAN filtering (`ifconfig bridge0 vlanfilter on`, member `tagged/untagged` sets — Arcana's `bridge` verbs access/trunk) is where "all packets bridged within a VLAN" are permitted or dropped: a vlan-filter ACE with accept/drop could be realised as the member's tagged-VLAN set. pf: no VLAN match. `frame-type` string: undefined vocabulary; cannot. |
| matches/l2/isid-filter {match-on-isid-filter} | PBB I-SID range/operator (802.1ah). | No PBB/MAC-in-MAC support in FreeBSD. Cannot. |
| matches/l3/ipv4/ipv4-fragment {operator (default match), type bits df/isf/ff/lf}; `must 'not(../acl:flags)'` | Fragment classification with operator. isf = is a fragment; ff = first fragment; lf = last fragment; df = DF bit. | ipfw `frag` family (FreeBSD 13+): `frag df` (DF set); isf = `{ frag mf or frag offset }`; ff = `frag mf not frag offset` (MF set, offset 0); lf = `frag offset not frag mf`; plain `frag` = non-first fragment (offset != 0). Operator: match (all listed types true) -> AND of the expressions; any -> or-block; not -> `not` on each / De Morgan. Example B.2 ("drop all fragments", type isf) -> `deny ip from any to any { frag mf or frag offset }` — note ipfw's `frag` alone would miss first fragments. pf: `fragment` (any fragment, after scrub). |
| matches/l3/ipv4/source-ipv4-prefix-list, destination-ipv4-prefix-list (ipv4-prefix-set-ref) | Reference to a prefix set instead of a literal. | `from table(<set>)` / `to table(<set>)`. Coexists with RFC 8519 literal prefixes (both may be present: literal AND set; a `must` is not defined, so the agent decides: treat as AND). |
| matches/l3/ipv4/protocol-set (protocol-set-ref) | Protocol set reference. | or-block of `proto`. |
| matches/l3/ipv6/ipv6-fragment | Same bits for IPv6 (df must be 0). Example B.2 v6: isf = packets with a Fragment header (44), including atomic fragments. | isf -> `ext6hdr frag` (presence of the Fragment header: matches the RFC's definition including atomic fragments); ff/lf -> ipfw has no IPv6 fragment-offset/MF match: cannot; df -> n/a. |
| matches/l3/ipv6/source-ipv6-prefix-list, destination-ipv6-prefix-list, protocol-set | | as IPv4 (`table(...)`, or-block). |
| matches/l3/ipv6/extension-header (iana-ipv6-ext-types:ipv6-extension-header-type) | Match an extension header value (number or name). | `ext6hdr <list>`: 0 Hop-by-Hop -> `hopopt`, 43 Routing -> `route` (`rthdr0`/`rthdr2` for specific routing types), 44 Fragment -> `frag`, 50 ESP -> `esp`, 51 AH -> `ah`, 60 Destination Options -> `dstopt`; 135 Mobility, 139 HIP, 140 Shim6 -> no ipfw keyword: cannot. ipfw walks the header chain, so presence anywhere matches. pf: no extension-header match (only `proto` of the final header). |
| matches/l4/tcp/flags-bitmask {operator, (mode) explicit-tcp-flag* identityref | bitmask uint16}; `must 'not(../acl:flags)'` | Flow-Spec-style flags: bitmask of the 12 low bits of bytes 13-14 (FIN 0x001, SYN 0x002, RST 0x004, PSH 0x008, ACK 0x010, URG 0x020, ECE 0x040, CWR 0x080, AE 0x100); operator bits not/match/any. | ipfw `tcpflags`: "match" = `(data & value) == value` -> `tcpflags <listed set flags>`; "not match" -> `not tcpflags ...`; "any" -> `{ tcpflags syn or tcpflags ack ... }`; "not any" (example B.1 null-attack, bitmask 4095) -> `tcpflags !fin,!syn,!rst,!psh,!ack,!urg` — but ECE, CWR, AE are outside ipfw's six flags: a bitmask touching 0x040/0x080/0x100 cannot be honoured by ipfw (pf `flags` knows E and W, not AE). Example B.6 (bitmask 2 = SYN, match) -> `tcpflags syn`. |
| matches/l4/tcp/source-tcp-port-set, destination-tcp-port-set (port-set-ref) | Port set references. | port list or `lookup src-port/dst-port <table>` (3.1). |
| matches/l4/udp/source-udp-port-set, destination-udp-port-set | | same. |
| matches/l4/icmp/icmpv4-set, icmpv6-set | ICMP type set references. | `icmptypes <list>` / `icmp6types <list>`; codes dropped (pf can). |

### 3.3 New actions (augment .../actions)

| Node | Meaning | ipfw |
|---|---|---|
| log-action {log-type identityref (local-log), log-id string (when local-log: "name of the log file")} | Complementary logging with a named local log. | `log` on the rule; `logdst syslog|ipfw0|rtsock` (FreeBSD 13+). `log-id` as a *file name* has no ipfw equivalent (ipfw logs through syslog security facility, the ipfw0 bpf tap, or the routing socket which Arcana's recorder consumes); the agent can map `log-id` to a syslog tag/program filter or to Arcana's own record stream name. Also usable: `tag <n>` action to mark packets for later `tagged` matches. Note RFC 8519 `logging` (log-syslog) and 9899 `log-action` can both be present; treat as OR. |
| counter-action {counter-type identityref (counter-name), counter-name* string (when counter-name)} | Update one or more named counters. | ipfw counters are per rule; named counters -> one non-terminal `count` rule per counter name placed just before the ACE's terminal rule, with the same match: `ipfw add N count <match> // counter:<name>`; the console aggregates counters with the same name across ACEs/devices. Alternative: `ipfw table` of type `number` cannot count; dummynet `queue` counters are not named either. |
| rate-limit decimal64 (fraction-digits 2, units bytes per second); `when "../acl:forwarding = 'acl:accept'"` | Accept but police at this rate. Example B.6: SYNs at 20.00 B/s. | dummynet: `ipfw pipe <p> config bw <N>bit/s [queue <q> slots]` (bytes/s * 8 -> bit/s; ipfw accepts `bit/s`, `Kbit/s`, `Bytes/s`), rule `ipfw add N pipe <p> <match>`. A pipe is a shaper (queue + delay) not a policer; to approximate a policer set a tiny queue (`queue 2` slots, or `droptail`) so excess is dropped. Continuation: the `pipe` action is terminal unless `net.inet.ip.fw.one_pass=0`, in which case the packet continues from the next rule — put `allow` right after, or rely on one_pass=1 meaning "accepted after shaping". Per-source policing (DDoS) would use `mask src-ip 0xffffffff` on the pipe (Arcana's QoS already emits `pipe N config bw ... mask src-ip`). Fractional bytes/s round to whole bits/s (dummynet granularity). pf: ALTQ only; FreeBSD pf has `max-pkt-rate` (packets, not bytes) on `pass` rules since 14 — not a byte rate. |

### 3.4 Everything else

- `defined-sets` has `nacm:default-deny-write` -> the cblink operations writing sets are `auth: true`.
- `mpls-acl-type` identity (base acl-base) -> an ACL type Arcana never advertises (no MPLS).
- `port-set` entries carry an `id` string key and a nested `choice port { container port-range-or-operator { uses packet-fields:port-range-or-operator } }` — a choice with a single container case, left open for future set kinds.

## 4. Cannot be mapped (with reasons)

| Node | Reason |
|---|---|
| mpls-values (traffic-class, label-position, label ranges, label-block-name, ttl-value), `mpls-acl-type` | FreeBSD has no MPLS forwarding or matching. |
| isid-filter | No Provider Backbone Bridging in FreeBSD. |
| vlan-filter as a packet match | ipfw/pf cannot read the 802.1Q TCI; only per-vlan-interface (`recv vlanN`) or if_bridge VLAN filtering approximations. `frame-type` has no defined values. |
| pattern (payload) in ipfw/pf | No byte matching; needs ng_bpf or Suricata via divert/netgraph. |
| ipv6-fragment ff / lf | ipfw has no IPv6 fragment-offset or MF match; only `ext6hdr frag` (isf). |
| extension-header 135 (Mobility), 139 (HIP), 140 (Shim6) | ipfw `ext6hdr` vocabulary: frag, hopopt, route, dstopt, ah, esp, rthdr0, rthdr2. |
| flags-bitmask touching ECE/CWR/AE in ipfw | ipfw tcpflags = fin,syn,rst,psh,ack,urg only. pf has E/W; nobody has AE. |
| icmpv4/icmpv6 set entries' `code`, `rest-of-header` in ipfw | ipfw matches types only (pf: code yes, rest no). |
| port-set with `neq` inside a table, or large ranges in tables | ipfw number tables hold values, not ranges or negations. |
| alias `fqdn`, `uri` as kernel matches | Not packet-header data; need DNS resolution into tables (fqdn) or the Squid URL filter (uri). |
| log-action/log-id as a log *file* | ipfw has no per-rule log destination file; syslog/ipfw0/rtsock only. |
| counter-action with counters shared by several rules as one kernel counter | ipfw counters are per rule; aggregation happens in the agent/console. |
| rate-limit as a true policer with exact bytes/s and burst | dummynet is a shaper; burst/queue parameters are not in the model. |
| `rate-limit` without accept | Model forbids it (`when`), ipfw would allow `pipe` on any rule. |
| network-level ACL/defined-set reuse, binding to VRF/device | Not in the published module; Arcana must define its own augment (fib/jail/all-interfaces). |

## 6. YANG constructs used (examples from RFC 9899) and what the cblink schema must express

| Construct | Example | Need in the YAML/CBOR schema |
|---|---|---|
| augment (many, at nested paths incl. inside choices) | `augment "/acl:acls/acl:acl/acl:aces/acl:ace/acl:matches/acl:l3/acl:ipv4/acl:ipv4" { container ipv4-fragment ... }`, `augment "/acl:acls" { container defined-sets ... }` | Cross-spec extension of an attribute set (new attributes added to `acl-ipv4` set from the enh spec); id ranges per module; augment targets inside choice cases. |
| identityref (base from another module) | `leaf offset { type identityref { base acl-enh:offset-type; } }`; `identity mpls-acl-type { base acl:acl-base; }` extends RFC 8519's type set | Open enumerations extensible across specs (see rfc8519.md). |
| leafref typedefs | `typedef port-set-ref { type leafref { path "/acl:acls/acl-enh:defined-sets/acl-enh:port-sets/acl-enh:port-set/acl-enh:name"; } }` | Reference checks against a list key held in the same family; dumps/edit need referential integrity (deleting a set in use must fail). |
| union | `leaf-list protocol { type union { type uint8; type string; } }`; IANA `icmpv4-type { union { uint8; icmpv4-type-name } }` | Union kind; the text member must be matched against an enumeration (name) or /etc/protocols. |
| bits typedef used as an *operator* | `typedef operator { bits { not(0); match(1); any(2) } }` with the prose rule "any and match must not be set simultaneously" | flags definition + a constraint the schema cannot state (must/handler). |
| bits with semantic defaults | `leaf operator { type operator; default "match"; }` | default of a flags value. |

| choice with a single container case | `choice payload { container pattern { if-feature ...; } }`, `choice port { container port-range-or-operator {...} }` | Same (degenerate). |
| must referencing sibling from the base module | `container ipv4-fragment { must 'not(../acl:flags)' ... }`, `container flags-bitmask { must 'not(../acl:flags)' }` | "Mutually exclusive with attribute X of the base set": a declarative exclusion between attributes of different modules. |

| when on a leaf | `leaf log-id { when "derived-from-or-self(../log-type, 'acl-enh:local-log')"; }`; `leaf rate-limit { when "../acl:forwarding = 'acl:accept'"; }` | Conditional validity on a sibling's value, incl. identity derivation. |
| when on a leaf-list | `leaf-list counter-name { when "derived-from-or-self(../counter-type, 'acl-enh:counter-name')"; }` | same |
| if-feature on containers inside choices | `container pattern { if-feature "match-on-payload"; }` | per-attribute feature gating. |

| decimal64 | `leaf rate-limit { type decimal64 { fraction-digits 2; } units "bytes per second"; }` | A fixed-point kind: CBOR can carry decimal fractions (tag 4) or the schema can define `decimal64` as int64 scaled by 10^fraction-digits (cblink `float` loses exactness; prefer scaled integer `s64` with `fraction-digits: 2` in the spec, encoded as integer hundredths or as CBOR tag 4). |

| rt-types:mpls-label | `type rt-types:mpls-label` (union of uint32 0..1048575 and an enumeration of reserved labels) | union + range. |

## 7. Open decisions and trade-offs

1. **Port sets: expansion vs number tables.** Expansion is exact but limited to 30 entries per rule
   and re-emits every rule when the set changes; tables change without touching rules but cannot
   hold ranges/negations compactly. Hybrid with a size threshold, or always expand and accept
   rule churn (the atomic set-swap makes churn safe).
2. **Prefix sets as ipfw tables: table budget.** `net.inet.ip.fw.tables_max` (128 default) is
   shared with SD-WAN steering tables; raise it at agent start (up to 65534) and name tables
   with a prefix (`acl.<set>`, `alias.<name>`) to avoid collisions with raw-ipfw users.
3. **Aliases.** Decompose at the console (into sets + ports + protocols) or at the agent? Console
   decomposition keeps the agent simple and makes fqdn/uri handling (DNS/Squid) a console/SD-WAN
   concern; agent decomposition keeps the device model faithful.
4. **Payload matching.** ng_bpf via ipfw `netgraph` gives exact offset semantics in kernel; Suricata
   gives richer content matching but with its own rule language and latency. Pick one or none for
   v1 and advertise `match-on-payload` accordingly.
5. **rate-limit semantics.** Shaper (dummynet pipe, delays packets) vs policer (drop excess). Decide
   the queue size used for "policing" and whether `one_pass` is 0 (continue after pipe) or 1 (pipe
   terminates); the choice affects every other dummynet user in the ruleset (Arcana QoS), so it must
   be a host-level decision, not per ACE.
6. **flags-bitmask with ECE/CWR/AE.** Reject such ACEs on ipfw hosts (error with extended ack) vs
   silently ignore the unsupported bits (dangerous). Reject.
7. **IPv6 fragments.** Only `isf` is exact; decide whether ff/lf requests are rejected or mapped to
   isf with a warning.
8. **log-id / counter-name.** Define Arcana semantics: log-id -> syslog tag or recorder channel;
   counter-name -> console-side aggregation of per-rule counters. Document that `counter-action`
   adds one `count` rule per name.
9. **Network-level objects.** The console is the owner of defined-sets and ACL definitions; devices
   get pushed copies. Decide the cblink shape: a device family that mirrors `/acls` (agent), and a
   console API that mirrors the same tree at network level with a device/binding list (the A.3/A.8
   requirements), using the same attribute sets.
10. **Extension headers vocabulary.** Map IANA names to ipfw keywords and reject the three that
    ipfw lacks, or accept them as "match nothing"? Reject.
